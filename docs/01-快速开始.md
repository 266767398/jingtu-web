# 01 · 快速开始（安装部署）

> 适用版本：server `1.3.0` / 启动日志 `V8.2`。三种方式任选：**Docker 面板一键（推荐）**、命令行 Docker、宝塔/裸机。

---

## 1. Docker 面板一键安装（推荐，最快）

### 1.1 准备

- 一台装有 Docker 的服务器（支持 1Panel、宝塔「Docker → 容器编排」、Portainer 等任意 Compose 面板）。
- 内存建议 ≥ 2GB（MySQL + Node 应用）。

### 1.2 操作步骤（以面板「Docker → Compose」为例）

1. 进入面板 **Docker → Compose（编排）→ 创建项目**。
2. **项目名称**：填写 `jingtu-web`（英文，面板自动建目录）。
3. **docker-compose.yml 来源**：选择 **从文件上传** 或 **直接粘贴**，内容使用仓库根目录的
   [`docker-compose.standalone.yml`](../docker-compose.standalone.yml)（一键版，无需额外 .env）。
4. 勾选 **「创建项目后立即启动」** → 点击 **确认**。
5. 面板开始拉取 `mysql:8.0` 与构建应用镜像（首次约 1~2 分钟）；两个容器进入 `running` 且 `jingtu-web` 健康检查通过即完成。
6. 浏览器访问 `http://服务器IP:3456`，首次打开进入 **建站向导**（/setup）。

> 若面板仅能填「模板/在线」来源，也可用命令行方式（见 §2）或把文件上传到服务器后
> `docker compose -f docker-compose.standalone.yml up -d --build` 启动。

### 1.3 一键版安全提示（必改项）

一键版内置一组「体验默认值」（已随仓库公开），**对外提供服务前务必在面板中修改**。
一键版已支持「面板环境变量覆盖」（compose 用 `${VAR:-默认值}` 引用）——在面板的
**环境变量/配置** 中设置同名变量即可覆盖默认值（如 1Panel：编排 → 该项目 → 环境变量；
宝塔：Docker → 编排 → 项目 → 编排模式切换），**设置即生效，无需手动改 compose 文件**：

| 变量 | 所在服务 | 说明 |
|---|---|---|
| `MYSQL_ROOT_PASSWORD` / `MYSQL_PASSWORD` | db / app | MySQL 账号密码 |
| `SESSION_SECRET` | app | 会话签名密钥，≥ 48 字节随机十六进制 |
| `ENCRYPT_KEY` | app | VRChat 凭据 AES-256-GCM 密钥，64 位十六进制 |

生成命令：

```bash
node -e "console.log(require('crypto').randomBytes(48).toString('hex'))"   # SESSION_SECRET
node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"   # ENCRYPT_KEY
```

改后重启 `jingtu-web` 容器即生效。**注意：更换 `ENCRYPT_KEY` 会使已保存的 VRChat Cookie 无法解密（需重新登录）；更换 `SESSION_SECRET` 会使已登录会话全部失效。**

### 1.4 绑定地址、端口与反代

- 一键版默认 `127.0.0.1:3456:3456`（只监听服务器本机）。
- 对外发布标准姿势：服务器 Nginx / 宝塔反代 80/443 → `127.0.0.1:3456`，同时把 `TRUST_PROXY` 改为 `1`。
- 确需直连暴露：把 `APP_BIND` 改为 `0.0.0.0` 并保持 `TRUST_PROXY: "0"`。
- 改端口：在面板「环境变量」设置 `APP_PORT=8080` 即可（无需改 compose 文件，见 §2.1）。

## 2. 命令行 Docker Compose 安装（生产推荐）

生产环境建议用「强校验版」compose（密钥缺失会拒启，杜绝弱口令）：

```bash
# 1) 准备环境变量（推荐独立文件，不污染 Node 的 .env）
cp docker.env.example docker.env
#    编辑 docker.env：填 JINGTU_DB_ROOT_PASSWORD / JINGTU_DB_PASSWORD / SESSION_SECRET / ENCRYPT_KEY

# 2) 构建并启动（app + mysql）
docker compose --env-file docker.env up -d --build

# 3) 检查就绪（返回 ok 即数据库可用）
curl -fsS http://127.0.0.1:3456/api/health/ready
```

常用运维命令：

```bash
docker compose logs -f app                     # 应用日志
docker compose exec app node db_init.js        # 手动执行迁移
docker compose down                            # 停止（数据在宿主机目录保留）
docker compose build && docker compose up -d   # 升级
ls ${STORAGE_ROOT:-./docker-data}              # 持久数据目录：mysql / uploads / backups / logs / assets / data
```

镜像说明：多阶段构建（`node:22-slim`）、非 root 运行、持久数据默认挂载到 compose 所在目录
`docker-data/`（可用 `STORAGE_ROOT` 自定义，见 §2.1），入口脚本自动「等库就绪 → db_init → 启动」。

### 2.1 自定义存储位置与端口（可选）

两个 compose 文件均已参数化，改配置**无需改文件**，只需设环境变量（命令行版写进 `docker.env`，面板版填进「环境变量」）：

| 变量 | 默认 | 说明 |
|---|---|---|
| `STORAGE_ROOT` | `./docker-data` | 持久数据宿主机根目录，自动创建子目录 `mysql/ uploads/ backups/ logs/ assets/ data/` |
| `APP_PORT` | `3456` | 宿主对外端口（映射到容器内 `APP_CONTAINER_PORT`） |
| `APP_BIND` | `127.0.0.1` | 宿主绑定地址；直连公网才改 `0.0.0.0`（保持 `TRUST_PROXY=0`） |
| `APP_CONTAINER_PORT` | `3456` | 高级：容器内应用自身监听端口（healthcheck 已同步跟随） |

示例（命令行版，追加到 `docker.env`）：

```bash
STORAGE_ROOT=/opt/jingtu/data        # Linux 绝对路径
APP_PORT=8080                        # 对外 8080 → 容器 3456
```

```bash
STORAGE_ROOT=D:/docker/jingtu        # Windows（正斜杠）
APP_PORT=9000
```

> ⚠️ **Linux 权限**：应用容器以 `node` 用户（uid=1000）运行，首次部署执行
> `sudo chown -R 1000:1000 $STORAGE_ROOT`（MySQL 数据目录由官方镜像入口自动 chown 为
> uid=999，无需手动处理；Docker Desktop / Windows / macOS 权限自动同步，免操作）。
> 更换 `STORAGE_ROOT` 属于「另起一套数据」，不会自动迁移旧数据。

## 3. SQLite 单机极简版（演示 / 低配）

不依赖 MySQL 的单容器模式（`JINGTU_DB_ENGINE=sqlite`，Node ≥ 22 内置 `node:sqlite`）。适合本地试玩、临时演示，不建议生产。在 `docker-compose.standalone.yml` 基础上删除 `db` 服务，app 服务改为：

```yaml
  app:
    build: .
    image: jingtu-web:latest
    restart: unless-stopped
    environment:
      NODE_ENV: production
      PORT: 3456
      TRUST_PROXY: "0"
      JINGTU_DB_ENGINE: sqlite
      JINGTU_SQLITE_PATH: /app/server/data/jingtu.sqlite
      SESSION_SECRET: "<改为随机值>"
      ENCRYPT_KEY: "<改为随机值>"
    ports:
      - "127.0.0.1:3456:3456"
    volumes:
      - jingtu_sqlite:/app/server/data
      - uploads:/app/uploads
      - logs:/app/logs
    healthcheck:
      test: ["CMD", "node", "-e", "require('http').get('http://127.0.0.1:3456/api/health/live',r=>process.exit(r.statusCode===200?0:1)).on('error',()=>process.exit(1))"]
      interval: 30s
      timeout: 5s
      retries: 5
      start_period: 20s

volumes:
  jingtu_sqlite:
  uploads:
  logs:
```

注意：SQLite 模式下 Session 回退 MemoryStore（重启后需重新登录），且无 `db` 服务健康依赖。

## 4. 宝塔面板安装

仓库提供一键脚本 `install.sh`（检测/安装 Node 20 → 装依赖 → 生成 .env 与密钥 → 建库 →
db_init → 生成 PM2 与 Nginx 反代配置）：

```bash
REPO_URL=https://github.com/你的名/jingtu-web.git \
DOMAIN=jingtu.example.com DB_NAME=jingtu_group DB_USER=jingtu_user \
DB_PASS='强密码' MYSQL_ROOT_PASSWORD='root强密码' \
bash install.sh
```

或手动方式（要点）：

1. 网站根目录 `public`；数据库建库 `jingtu_group`（utf8mb4）。
2. Node 项目管理：启动文件 `server/server.js`，运行目录 `server`，**实例数必须为 1**（不支持 cluster）。
3. 反向代理目标 `http://127.0.0.1:3456`（模板见 [`deploy/nginx/jingtu.conf`](../deploy/nginx/jingtu.conf)）。
4. 根目录 `.env` 按 [`.env.example`](../.env.example) 填写。

## 5. 裸机安装（Node + MySQL）

```bash
git clone https://github.com/你的名/jingtu-web.git && cd jingtu-web
cd server && npm ci --omit=dev            # 安装生产依赖
# 建库：CREATE DATABASE jingtu_group CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;
#   建账号并授权（见 .env.example）
cp ../.env.example ../.env                # 编辑：MYSQL_*、SESSION_SECRET、ENCRYPT_KEY、CORS_ORIGINS
node db_init.js                           # 建表/迁移（幂等，可重复执行）
npm start                                 # 启动，监听 3456
```

进程守护（PM2，单实例）：

```bash
npm i -g pm2 && pm2 start ecosystem.config.js && pm2 save && pm2 startup
```

> 运行要求：Node ≥ 20.9.0（SQLite 模式需 ≥ 22）、MySQL 5.7+ / 8.0+；TLS 由外部 Nginx 终结。

## 6. 首次启动与初始化

1. 访问 `http://服务器IP:3456`，进入建站向导 `setup.html`（六步：环境检查 → 数据库连接 →
   邮件（可跳过）→ 创建超级管理员 → 完成）。向导不会建表，需已在容器/服务启动时执行过 `db_init.js`。
2. 用超级管理员登录 → 「我的 → 系统设置」：
   - 填写站点对外地址（`APP_URL`）、`CORS_ORIGINS`；
   - 配置 VRChat 群组接入（`VRC_API_KEY` / `VRC_GROUP_URL`）；
   - 如启用「在线更新」按钮，可一键 `git fetch + merge --ff-only + 自动重启`（仅超管，跨平台）。
3. 安全基线检查见 [03-部署与运维.md §6](03-部署与运维.md#6-生产安全必检)。
