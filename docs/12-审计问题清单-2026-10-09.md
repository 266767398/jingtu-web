## 二、VRChat 绑定登录系统账号检查

> 专项核查结论：**系统账号链路（`vrc_auth.js`）质量高**——自动重登熔断/退避、TOTP 自动二次验证、
> cookie 双候选降级、失效标记、密文不外泄（P3-80）、软性过期配置均已妥善处理，未发现缺陷。
> 用户绑定/登录链路发现 4 项问题，见下。

### P1（🔴）已绑定 + 开启 2FA 的用户无法通过 VRChat 登录

- **现象（Symptom）**：`POST /api/auth/vrchat-login` 第一步（模式 A）在账号需要 2FA 时，
  [auth_vrc_service.js L177-194](file:///d:/phpstudy_pro/WWW/jingtu-web/server/auth_vrc_service.js#L177-L194)
  先按 `vrcUser.id` 查询绑定。但 VRChat `/auth/user` 在 2FA 待验证阶段返回的响应体只有
  `{ requiresTwoFactorAuth: [...] }`，**不含 `id`**（本文件 L429-435 注释已确认该上游行为）。
  于是 `WHERE vrchat_id = undefined` 必然查不到 → 返回 `"该VRChat账号未绑定本站账号"` →
  前端 [auth.js L472/L501](file:///d:/phpstudy_pro/WWW/jingtu-web/public/js/auth.js#L472-L501) 展示绑定引导。
- **来源（Source）**：对上游契约的误用（VRChat 2FA 挑战阶段无 `id`），与绑定流程已处理的同源问题
  （L428-445 有"拿不到 ID 就中止"守卫，登录流程却未同样处理）。
- **影响（Consequence）**：已绑定且开启 2FA 的用户**永远无法通过 VRChat 登录**——第一步就被引导去"重新绑定"，
  用户困惑且功能阻断；本地密码 + 2FA 登录不受影响，但 VRChat 快捷登录形同虚设。
- **修复方向（Remedy）**：模式 A 中当 `login.needs2fa === true` 时**先不查绑定**，生成 `loginToken`
  走 2FA 第二步；第二步 `verifyVrc2fa` 拿到真实 `id` 后再查绑定并完成登录（与绑定流程 V6.12 守卫同口径）。
  建议新增回归测试：mock 2FA 第一步响应（无 `id`），断言不落入"未绑定"分支。
- **处理状态**：✅ 2026-10-09 已修——模式 A 在 `needs2fa` 时先进入 2FA 流程并返回 `need2fa`；
  模式 B 与独立端点 `/vrchat-2fa` 均改为 2FA 验证通过拿到 `vResult.user.id` 后才查绑定 + 锁定/审核检查；
  新增静态回归测试锁定（security-regressions P1）。

### P2（🟡）绑定临时 token 永不过期，内存随放弃流程无限增长

- **现象**：[auth_vrc_service.js L45-56](file:///d:/phpstudy_pro/WWW/jingtu-web/server/auth_vrc_service.js#L45-L56)
  清理循环只删除 `expireAt` 非空的 token；而绑定 token 写入时 `expireAt: null`（L388-393），
  且成功/失败/换用户路径之外没有兜底清理。
- **来源**：设计时"绑定不设时间限制"的权衡（注释 L384-386），但遗漏了"用户放弃流程"这一常态路径。
- **影响**：每次有人发起绑定但中途离开（等邮件验证码超时、关闭页面），token 永久留存；
  配合限流 30 次/15 分钟，攻击者可缓慢灌入 → `bindTokens` 长期增长（内存泄漏面）。
- **修复方向**：给 `bindTokens` 增加合理有效期（如 24h）或按 `userId` 同用户去重（新绑定请求覆盖旧 token），
  清理循环统一按 `expireAt` 处理。

### P3（🟡）session 双 cookie 字段冗余（vrchatCookie / vrcCookie）

- **现象**：[auth_session.js L27](file:///d:/phpstudy_pro/WWW/jingtu-web/server/auth_session.js#L27) 写
  `req.session.vrchatCookie`；[auth_vrc_service.js L491](file:///d:/phpstudy_pro/WWW/jingtu-web/server/auth_vrc_service.js#L491)
  写 `req.session.vrcCookie`；读取方（[vrc_auth.js L587](file:///d:/phpstudy_pro/WWW/jingtu-web/server/vrc_auth.js#L587)）
  用 `vrchatCookie || vrcCookie` 双轨兜底，解绑时两套都清（L535-542）。
- **来源**：命名不一致（`vrchatCookie` vs `vrcCookie`），历史迁移未归一。
- **影响**：两套字段语义相同却命名不同，检索/审计成本高，易出现"只清一套"的回归。
- **修复方向**：统一为 `vrchatCookie`；保留读取端 `|| vrcCookie` 兼容即可，写路径一律用 `vrchatCookie`。

### P4（🟢）登录成功收尾块三重复

- **现象**：[auth_vrc_service.js L159-170](file:///d:/phpstudy_pro/WWW/jingtu-web/server/auth_vrc_service.js#L159-L170)、
  L219-229、L297-307 三处结构相同：`UPDATE users SET vrchat_name/vrchat_avatar_url/failed_login_attempts/locked_until`
  → `session.regenerate` → `buildSession` → `save` → `INSERT sys_oper_log` → `insertVrcLoginHistory`；
  另有 `avatarUrl` 兜底逻辑三段重复（L148-150 / L209-214 / L289-291）。
- **来源**：Duplicate Code（Fowler — Refactoring）。
- **影响**：修复一处登录缺陷需同步三处；上次"displayName 冲成 NULL"类 bug 正是此类重复导致漏改。
- **修复方向**：抽 `completeVrcLogin(req, boundUser, cookie, reason)` 收尾函数，三处统一调用。

### 系统账号链路确认无缺陷项

- 自动重登：F-30 熔断/退避/最小间隔、TOTP 自动完成、无凭据被动分支（不产生重登风暴）——正确。
- cookie 管理：`getVRCCookie` 用户绑定优先 → 系统账号降级；`invalidateVRCCookie` 只清用户 cookie、
  系统 cookie 由管理面板独占——正确（V8.2 注释明确）。
- 安全：cookie/凭据 AES-256-GCM 加密落盘、解密失败不写回、密文绝不透传上游——正确。
- ⚠️ 运维提醒：当前环境系统 VRC cookie 过期（`/api/avatar/user` 回源 502）属环境问题，
  需在管理面板重新登录系统 VRC 账号（含 TOTP）；`autoRelogin` 会按退避策略尝试自动恢复。

- **现象**：[collections.js L62-64](file:///d:/phpstudy_pro/WWW/jingtu-web/public/js/collections.js#L62-L64) 调用

- **来源**：重构/全局命名迁移时遗漏（Feature Envy + 悬空契约；Hyrum's Law 反向——调用方依赖了从未存在的接口）。
- **影响**：
  - `isLoggedIn()` 恒 false → [L583](file:///d:/phpstudy_pro/WWW/jingtu-web/public/js/collections.js#L583) 收藏操作被拦截、

  - `toast()` 恒走 `console.log` → 用户操作失败无任何提示；
  - `__defaultAvatar` 为空 → 无缩略图条目 src/背景为空（坏请求/空白卡）；
  - 同问题波及 [vrc_favorites.js L95](file:///d:/phpstudy_pro/WWW/jingtu-web/public/js/vrc_favorites.js#L95)（卡片缩略图）。
- **修复方向**：在 core.js/auth.js 补齐这 5 个全局的声明（`__toast → toast`、`__isLoggedIn → 登录态判断`、
  `__user → currentUser`、`__isAdmin → 角色判断`、`__defaultAvatar → '/api/avatar/default'`），

- **处理状态**：✅ 2026-10-09 已修——core.js 用 `Object.defineProperties + getter` 补齐 5 个兼容别名
  （实时反射 `currentUser` 登录态/角色与 `/api/avatar/default`），`window.__toast` 桥接到全局 toast；
