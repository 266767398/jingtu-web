# 03 · 部署与运维

> 安装步骤见 [01-快速开始.md](01-快速开始.md)；更早的运维记录已并入本文档体系（`docs/archive/` 已清理，历史变更见审计/报告清单）。

> **入口速查**：本机浏览器 → `http://localhost`（Nginx 80 反代）；局域网设备（飞牛 / NAS）→ `http://<本机IP>:3456`（Node 直连）。端口与访问形态详见 §8。

## 1. 健康检查

| 端点 | 含义 | 返回 |
|---|---|---|
| `/api/health/live` | 进程存活（不依赖数据库） | 200 |
| `/api/health/ready` | 就绪（`SELECT 1` 成功才算，DB 挂返回 503） | 200 / 503 |
| `/api/health` | 通用探活 | 200 |
| `/api/health/detailed` | 详细状态（管理员） | JSON |

> 以 `ready` 为就绪标准，而非“端口在不在”。Docker compose 已内置 healthcheck。

## 2. 日志

- 文本日志：`logs/YYYY-MM-DD.log`（Docker 输入 `docker compose logs -f app`）。
- 在线更新/重启排程日志：`logs/restart-<pid>-<ts>.{out,err}.log`。
- 运维面板日志：`logs/site.log`、`logs/panel.log`。

## 3. 备份与恢复

- 每日 02:30 自动备份（`auto_` 前缀），数据库导出 + `uploads/` 打包，保留策略：
  `FILE_RETENTION_DAYS`（默认 90）/ `BACKUP_RETENTION_DAYS`（默认 7）。
- 手工备份：内置 `/api/admin/backups/*`（管理员 + CSRF），备份口令经 `MYSQL_PWD` 传参防 ps 泄露。
- 恢复前先停止写流量并保留一份现网备份；恢复演练至少每月一次。

## 4. 升级 / 回滚

**Docker：** `docker compose build && docker compose up -d`（数据在宿主机目录 `STORAGE_ROOT` 下，默认 `./docker-data`，见 01-快速开始 §2.1）。若有 `server/package.json`
变更，compose 会重新 `npm ci`，无需手动安装。

**宝塔 / 裸机：**

```bash
git pull --ff-only
cd server && npm ci && node db_init.js
pm2 restart jingtu-web        # 或重启你的进程守护
curl -fsS http://127.0.0.1:3456/api/health/ready
```

**在线更新按钮（超管 · Git 一键）：** 后台「系统设置 → 🔄 在线更新」：
git fetch → ahead/behind 保护 → `merge --ff-only` → 检测 server 依赖并安装 → 可选「自动重启」。
重启排程**跨平台**：Windows 用 WMI 中继，Linux/macOS 用独立会话 helper（杀旧进程后拉起新服务，约 2~3 秒中断）。
仅超管可调 + CSRF + execFile 数组直传；更新绝不执行 `git clean`，`.env/`、`uploads/`、`assets/`、
`server/data/*.sqlite` 均在 `.gitignore` 内不受影响。

**回滚：** 针对已标记版本反向应用 `git revert`（勿强制重置共享分支），并核对 DB 变更方案。

## 5. 常见故障排查

| 现象 | 排查 |
|---|---|
| 端口在但页面无响应 | 查 `ready`；DB 挂会 503 |
| Node 18 / 启动即崩 | 必须 ≥20.9.0（sharp 0.35 要求），SQLite 模式需 ≥22 |
| 反代后客户端 IP 全为 127.0.0.1 | `TRUST_PROXY` 未设 1（按实际跳数） |
| 登录频繁被限 | 登录 15 分钟 5 次（成功跳过）；确认 `TRUST_PROXY` 正确，避免伪造头绕过 |
| 任意账号登录都 500（`ER_WRONG_VALUE` / 1525） | 多为 SQL 把 `''` 与 DATETIME 列比较（如 `deleted_at = ''`），MySQL 8.0 严格模式报 1525，5.7 宽松模式不报；统一改用 `deleted_at IS NULL`（2026-10-04 已全站修复） |
| 上传 413 | 前端 `requestSizeLimiter` 分档 + Nginx `client_max_body_size 200m` 同步 |
| 会话重启即失效 | SESSION_SECRET 未持久化或 SQLite 模式（MemoryStore） |
| 已存 VRCat 凭据解密失败 | ENCRYPT_KEY 被更换（这是设计行为，需重新登录） |

## 6. 生产安全必检

1. `SESSION_SECRET` / `ENCRYPT_KEY` 持久化、权限 600、纳入备份与轮换。
2. `CORS_ORIGINS` 限定具体域名（未配置会告警并接受任意来源）。
3. HTTPS + `TRUST_PROXY` + Secure Cookie 联合验证（登录后 `connect.sid` 应带 `Secure; HttpOnly; SameSite=Lax`）。
4. 防火墙只开 80/443（及 SSH）；`3456`、`3306` 不暴露公网（局域网内需飞牛/NAS 直连 3456 时可单独放行该端口）。
5. 屏蔽 `/api-docs`、`/api-docs.json` 公网访问。
6. 备份覆盖 MySQL + `uploads/` + 密钥，并做恢复演练。
7. 服务账号只写 `uploads/backups/logs`，不递归写整个仓库。
8. 进程守护**单实例**（不支持 cluster：CSRF/WS 在线映射/VRC 状态在内存）。

## 7. 加速基础镜像拉取（Docker registry-mirrors）

**为什么：** Docker Hub 官方源在国内拉取极慢/易超时；飞牛内置加速器
`docker.fnnas.com` 已失效（拉取报 `401 Unauthorized`）。

**本项目已内置加速，无需执行任何命令：**

- `Dockerfile`：默认基础镜像 `NODE_IMAGE=docker.1ms.run/library/node:22-slim`；
  需要官方源时 `--build-arg NODE_IMAGE=node:22-slim` 覆盖。
- `docker-compose.yml` / `docker-compose.standalone.yml`：MySQL 镜像
  `docker.1ms.run/library/mysql:8.0`。
- `docker-compose.fnos.yml`：busybox / mysql / node 三镜像均走 `docker.1ms.run` 前缀。

飞牛用户直接按 `docker-compose.fnos.yml` 顶部注释操作（Docker → 项目 → 粘贴文件 →
保存并启动）即可，**不需要 SSH / daemon.json**。

**可选：daemon 级全局加速（仅对手动 `docker pull` 等未带前缀的 docker.io 镜像生效）。**
本项目内置源为 `docker.1ms.run`（1Panel 官方维护，2026-10 实测可达），备选
`hub.rat.dev`；公共加速源无 SLA，失效时按上表换源或通过 `--build-arg` 覆盖
（阿里云个人加速器已停止同步最新镜像、网易/中科大等老站已关停，勿用）。

**飞牛 fnOS（SSH 操作，重启 Docker 会短暂中断容器，请在维护窗口执行）：**

```bash
sudo mkdir -p /etc/docker
[ -f /etc/docker/daemon.json ] && sudo cp /etc/docker/daemon.json /etc/docker/daemon.json.bak
sudo tee /etc/docker/daemon.json <<'EOF'
{
  "registry-mirrors": [
    "https://docker.1ms.run",
    "https://hub.rat.dev"
  ]
}
EOF
sudo systemctl daemon-reload
sudo systemctl restart docker
```

**验证：**

```bash
docker info | grep -A 5 "Registry Mirrors"   # 应列出上述三个源
docker compose -f docker-compose.fnos.yml up -d --build --force-recreate
```

> 注意：`registry-mirrors` 只对 docker.io（Docker Hub）生效，GHCR 等其它仓库不适用；
> 重启 Docker 后先用 `docker compose ps` 确认 db/app 恢复 healthy 再继续后续操作。

## 7.1 时区（Docker 自动同步）

- `docker-compose.yml` / `.standalone.yml` 的 app 服务设 `TZ=auto`：入口脚本按 IP 归属判断中国 IP 自动生成
  `Asia/Shanghai`，否则 UTC（实质等价 `env.tz`）；db 服务同步设 `DB_TZ=Asia/Shanghai` + MySQL 连接时区 `+08:00`，保证与定时任务对齐。
- 若容器时间差 8 小时：检查 `.env` 是否手写覆盖 `TZ`，删掉后重建 app/db 容器即可；数据不受影响。

## 8. 入口与端口（本机 / 局域网）

### 8.1 两种访问形态

| 访问方 | 地址 | 路径 | 说明 |
|---|---|---|---|
| 本机浏览器 | `http://localhost` | Nginx 80 → 反代 Node 3456 | 规范本机入口 |
| 本机浏览器 | `http://localhost:3456` | Node 直连 | 页面导航 302 到 80 同路径（API/静态/WS 不跳） |
| 局域网设备（飞牛 / NAS） | `http://<本机IP>:3456` | Node 直连 | **不跳转**，正常出页面 |
| 局域网设备（飞牛 / NAS） | `http://<本机IP>` | Nginx 80 → 反代 Node 3456 | 可选，同样可用 |

入口归一逻辑位于 `server.js` 顶部：仅当 `Host` 为 `localhost:3456` / `127.0.0.1:3456` 且请求为页面导航（`Accept: text/html`）时 302 到 80；局域网 IP 直连一律放行，避免跳到设备自身的 `localhost`。

### 8.2 绑定地址 `APP_BIND`

| 值 | 效果 | 适用 |
|---|---|---|
| `0.0.0.0`（默认） | 监听全部网卡，局域网可达 | 需要飞牛 / NAS 等设备直连 3456 |
| `127.0.0.1` | 仅本机回源，局域网不可达 | 只允许经 80 访问的纯本机部署 |

修改 `.env` 后需重启 Node 进程生效。

### 8.3 飞牛 / NAS 访问 3456 排查

1. 确认 Node 实际监听：`netstat -ano | findstr :3456` 应显示 `0.0.0.0:3456`（而非 `127.0.0.1:3456`）。
2. 确认设备与本机同一网段，能 `ping <本机IP>` 通。
3. Windows 防火墙若开启，需放行 3456/TCP 入站；防火墙关闭时无需额外配置。
4. 走 EasyTier / Radmin VPN 等组网时，用对应虚拟网卡 IP + `:3456` 访问。
5. WebSocket 与 HTTP 同源，局域网 IP 访问时 `Origin` 与 `Host` 一致即放行（`ws_service.js` 同源兜底），无需额外配置。

### 8.4 公网 IPv6 接入（DDNS）

链路：`外网 IPv6 → 反代 [::]:80/443 → 127.0.0.1:3456 → app 容器 → db 容器（容器内 IPv4）`。

**容器网络不需要开 IPv6**（Docker 默认 bridge 不支持，也无需支持）：IPv6 由宿主机反代/端口映射在入口终结，容器内继续走 IPv4。

1. **确认公网地址**：`ip -6 addr show` 看到 `240e:/2408:/2409:` 开头的 global 地址；`ip -6 route show default` 有默认路由。
2. **反代监听**：`deploy/nginx/jingtu.conf` 已含 `listen [::]:80/443`。校验实际监听：`ss -6 -lntp | grep -E ':(80|443)\b'`；无输出则补 `listen [::]` 后 `nginx -t && systemctl reload nginx`。
3. **反代为容器时**：端口映射写 `"[::]:80:80"` / `"[::]:443:443"`（宿主 IPv6 → DNAT → 容器 IPv4），容器内 Nginx 仍需监听 `[::]`。
4. **飞牛 fnOS 自带反代**：面板 IPv6 开关打开；若面板生成配置不含 `listen [::]`，手工补后勿再在面板重存该条（会被覆盖）。
5. **DDNS**：加 **AAAA 记录**指向 NAS IPv6（Dynv6 / DuckDNS / No-IP 等），确认客户端自动刷新——**IPv6 前缀动态，光猫重启即变**。
6. **防火墙**：路由器 IPv6 入站放行 80/443；`3306` 与 `3456` 不放行公网。`APP_URL` / `CORS_ORIGINS` 填 `https://域名`（高位端口则带端口）。
7. **验证**：`curl -6 -g "http://[IPv6地址]/api/health/ready"` → `nslookup -type=AAAA 域名` → `curl -6 "https://域名/api/health/ready"`。
8. **运营商封 80/443**：裸地址都不通即为入站被封，改高位端口（如 `[::]:8443`，同步 `APP_URL`）或走隧道；HTTP-01 证书签发也需 80 可达，否则改用 DNS-01 / 导入证书。
