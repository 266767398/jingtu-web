# 境途同游 V7.10 — 玩法乐趣功能规划

> 创建日期：2026-08-01
> 版本：V7.10（玩法扩展规划版）
> 核心理念：**不设会员充值系统，所有功能和奖励通过参与社群活动免费获得**
> 文档性质：**规划文档，不是已实现功能清单、当前数据库说明或 API 契约**

> [!IMPORTANT]
> ## 当前实现边界（截至 2026-08-09 当前检入）
>
> - **已存在的基础能力：** `server/routes/checkin.js`、`server/routes/achievements.js` 已挂载到 `/api/checkin`、`/api/achievements`；`server/db_init.js` 已创建 `user_checkin`、`checkin_rewards`、`achievements`、`user_achievements` 及用户签到/成就积分字段。基础签到、状态/历史、签到奖励读取，以及签到/成就排行榜读取 API 已存在。
> - **签到奖励不是本文“统一星光”：** 当前签到写入的是 `checkin_points`，默认连签档位由 `checkin_rewards` 配置为 1/3/7/14/30/60/100 天对应 10/30/70/150/300/600/1000 积分；它与下文拟议的星光获取、倍数、彩蛋和统一账本不同，不能混称为已落地星光系统。
> - **成就仅部分接线：** `db_init.js` 中有 29 条成就定义，成就查询/解锁基础 API 存在；当前业务触发调用只在签到路由中接入，发帖、点赞、评论、活动、聊天、相册、会员时长、VRChat 等定义尚未接入自动触发。
> - **签到/成就前端目前未启用：** `public/js/checkin.js`、`public/js/achievements.js` 及对应 CSS 文件虽已存在，但 `public/index.html` 未加载它们，属于休眠代码，不能视为公开页面已经上线。
> - **生日当前边界：** `public/index.html` 会加载 `public/js/birthday.js`；现有功能是读取成员生日列表，并由管理员手动创建、编辑、删除 `event_type='birthday'` 的普通活动。零点自动祝福、自动礼包/双倍奖励、自动主题、广播、祝福墙等“生日惊喜”均未实现。
> - **本文其余均为未实现提案：** 统一星光/等级、运势、签到彩蛋、幸运转盘、扩展成就、综合排行榜及自动结算奖励、商城/装扮、任务/社群挑战、夸夸墙、互动游戏、时光机/年度报告、自动生日惊喜、投票、个人/社群数据仪表盘均未实现。下文出现的 SQL、路由、文件名、数值、工期均为候选设计，不代表当前 schema、接口或静态资源。

## 一、设计理念

### 1.1 核心原则

| 原则 | 说明 |
|------|------|
| **零付费** | 所有功能、装扮、道具均通过活跃参与免费获取，不设任何付费入口 |
| **趣味驱动** | 用游戏化机制激励社群参与，而非强制任务 |
| **正向社交** | 所有玩法促进成员之间的友好互动，杜绝负面竞争 |
| **轻量克制** | 趣味功能不喧宾夺主，不影响核心社群管理功能的使用 |

### 1.2 激励闭环

```
参与社群活动 → 获得积分/经验 → 升级/解锁装扮 → 展示个性 → 更多参与动力
     ↑                                                          |
     └──────────────────── 正向循环 ─────────────────────────────┘
```

## 八、匿名夸夸墙（未实现提案）

### 8.1 功能设计

一个完全匿名的正向留言板，成员可以：

- 发送匿名夸奖/感谢/鼓励消息给特定成员
- 查看别人给自己的夸夸（不知道是谁发的）
- 每天限发 3 条夸夸消息
- 被夸赞的成员收到通知但不显示发送者

### 8.2 防滥用机制

| 机制 | 说明 |
|------|------|
| 每日限额 | 每人每天最多 3 条 |
| 敏感词过滤 | 自动过滤不良内容 |
| 举报机制 | 接收者可以举报（匿名） |
| 管理员监控 | 管理员可查看违规内容处理 |

### 8.3 夸夸墙展示

- 首页展示"今日最暖夸夸"（精选 3 条）
- 被夸最多的成员登上"人气夸夸榜"
- 获得 10 次夸夸解锁「人见人爱」成就
