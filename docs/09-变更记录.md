## 2026-10-05 · 群组玩家头像不显示修复（/user 限速在缓存命中之后）

现象：群组页一屏多位玩家同时打开时，头像集体显示为默认占位图（SVG 灰底小人）。

根因（生产实测定位）：`/api/avatar/user` 路由的**每 IP 60/min 限速在缓存命中判断
之前执行**——与 `/proxy` 已修复的「缓存命中不消耗限速配额」逻辑相反。整群成员
头像经 `lazyLoadGroupAvatars`（BATCH=12、GAP=400ms）集中请求 `/user`，前 60 个
请求无论是否命中 10min 内存缓存都消耗配额（实测：同一 uid 连发 62 次，前 60 次
302、第 61 次起全部降级为占位图），随后配额耗尽 → 全体成员头像降级为占位图。

修复（`server/routes/avatar.js`）：
- **缓存命中先于限速**：`/user` 路由先查 `_userAvatarCache`（10min 成功 / 5min 失败
  TTL），命中即 302 到 `/proxy` 或直接返回占位，**不消耗配额**。
- **限速仅对「回源解析」计费**：限速检查移到 `resolveUserAvatarUrl()` 调用之前，
  即真正要调 VRChat 用户 API 时才计数；未登录请求（第 1 步即返回）也不消耗配额。
- 保留 P3-119 的 XFF 信任策略（仅回环直连才采信 `x-forwarded-for`），防止客户端
  直接连时轮换桶绕过每 IP 限速。
- 新增 1 条回归断言（`/user` 内 `_userAvatarCache.get(uid)` 必须先于
  `userAvatarRateLimited(clientIp)` 出现）；全量 817 项测试通过，lint 0 错误。

## 2026-10-05 · presence/contribute 请求中止修复（ERR_ABORTED）

现象：浏览器控制台报 `net::ERR_ABORTED http://…:3456/api/group/presence/contribute`。

根因：前端 `contributePresence()` 只给 20s 超时，而服务端要串行拉取贡献者
**全量好友列表**（`maxPages:20` × 在线/离线两遍 = 最坏 40 页请求，每页还受全局
40/min 令牌桶约束可能排队最长 12s）。国内访问 api.vrchat.cloud 延迟高时链路轻易
超过 20s → 浏览器 abort（ERR_ABORTED），且 `silent:true` 吞掉错误——贡献永远
静默失败；服务端则继续白耗共享 VRChat 配额（server 超时 120s 远大于客户端）。

修复（`groups_members_sync.js` + `group.js`）：
- **收紧好友分页预算**：`maxPages:20 → 5`（≤500 在线 + ≤500 离线好友）。贡献
  状态只服务本群成员（通常远小于此规模），最坏 40 请求降为 10，从根上缩短链路。
- **客户端中断止损**：写入循环内检测 `req.aborted || res.destroyed`，客户端超时
  abort / 关页时立即停止消耗 VRChat 配额与 DB 写入，`aborted` 标志经结果回传后
  跳过 `ok(res,…)` 响应发送（避免对已销毁连接写响应）。
- **前端超时 20s → 60s**：覆盖正常耗时（10 页串行 + 令牌桶排队）与止损之间的平衡。
- 新增 2 条回归断言（前端超时 ≥60s / 服务端分页≤5 页 + 中断止损）；缓存戳
  `loader.js 20261005d→e`（懒加载 group.js 失效重取）；全量 816 项测试通过。

## 2026-10-05 · 登录头像显示修复（Cookie 门控反枚举）+ VRChat 冷却表防泄漏

### 登录界面头像不显示

根因：`/api/auth/preview` 自 22dfd7c 起为防账户枚举（M-2），匿名请求一律返回 `null`
（不查库、关闭预言机），登录页因此永远只显示默认头像。

修复方案（依据 §11.8.3 登录头像预览 + 用户确认的「仅记住的账号真头像」方案）：
- **HttpOnly 记住账号 Cookie（`jingtu_remember_login`）**：`POST /login` 携带
  `remember=true` 时下发（180 天，`httpOnly + sameSite:lax`，生产环境 `secure`）；
  未勾选记住与 `POST /logout` 时清除。服务端手写 `readCookie()` 解析，不引入
  cookie-parser 依赖。
- **/preview 门控**：匿名请求仅当 `loginId` 与该浏览器记住的账号完全匹配时才返回
  真实头像；不匹配一律 `{ avatarUrl: null, vrchatAvatarUrl: null }` 且**不查库**
  ——白名单保持关闭，无新增枚举面。已登录会话不受影响。
- **前端占位图降级**：新增 `loginAvatarPlaceholder()` → `/api/avatar/default?name=<首字>`
  （服务器 SVG 生成器）；`previewLoginAvatar()` 空数据/失败时降级为占位图而非空白。
- **实时预览**：登录页账号输入框新增 input 事件（350ms 防抖）+ 密码框
  聚焦触发，输入邮箱即出初始/真实头像。

### VRChat 模块漏洞修复

审查 `vrc.js`（全局限流令牌桶 40/min）→ `avatar.js`（SSRF 白名单 / L1-L2 缓存 /
CDN token 200/min）→ `media_providers.js`（failover+熔断 / 重定向 SSRF 防护）→
`groups_members_sync.js` 后，修复唯一缺陷：

- **`lastRefreshByUser` / `lastSyncByUser`「按用户冷却」Map 无限增长**：用户名可枚举
  且无清理，长期运行内存泄漏。修复：新增 `pruneCooldownMap(map, cooldownMs)` helper，
  仅在 Map 超过 1000 条时惰性清扫过期两倍冷却窗口的条目（O(n) 摊薄、不阻塞请求），
  sync 与 refresh 两条路径各接一个调用点。

### 测试与缓存

- 新增 4 条测试：匿名记住账号匹配返回真实头像 / 匿名不匹配一律 null 且不查库 /

## 2026-10-03 · VRChat API 实测（连通性/风险/选型结论）

- 实测链路全部通过：上游 `api.vrchat.cloud/api/1/config` → HTTP 200；项目 `server/vrc.js` 封装层
  `/config`、`/time` → 均 200；本地 `/api/health` → 200；`/api/vrc-monitor` 未登录 → 401（守卫正常）。
- 风险结论：政策红线（Tupper Policy：禁 avatar ripping/客户端修改/自动化刷接口）、接口随时破坏性变更、
  账号风控、cookie 隐私均已由内置 40/min 限流、moderation 仅人工触发、写操作限本人绑定 cookie 覆盖。
- 选型结论：**代码层维持手写 `server/vrc.js`**（限流/安全/多账号定制均在），**参考层用官方 OpenAPI**
  （`ai-scratch/vrcapi-spec/` 作权威说明书）；不建议引入官方 npm SDK（会丢失限流与安全层）。
