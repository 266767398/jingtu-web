## 2026-10-05 · VRChat 玩家头像不显示修复

用户实测：群组页玩家头像大面积不显示（占位图）。经三组实测定位两条独立断链：

```
1) api.vrchat.com/api/1/users/{id}/image（前端兜底）→ 307 → api.vrchat.cloud → 404
   （VRChat 已弃用该端点，旧兜底是死链）
2) assets.amlcdn.com（VRChat 老式缩略图 CDN）→ TLS 握手被阻断（国内多数网络直连不可达）
   → 代理回源约 19s 超时（此前日志 GET /api/avatar/proxy 耗时 19.4~19.9s 即此因）
3) api.vrchat.cloud 本身可达（/visits 200，/users/{id} 需鉴权但连通正常）
```

修复：
- **后端新增 `GET /api/avatar/user?u={vrchatId}`**（server/routes/avatar.js）：
  用系统 VRChat 账号会话调用 `/users/{id}` 解析真实头像文件 URL（需要鉴权，这也是
  `/users/{id}/image` 旧链路拿不到图的原因之一），校验域名白名单后 302 到 `/proxy`
  复用 L1/L2 缓存、CDN 令牌桶与多源 failover；内置 10min 成功缓存 / 5min 失败冷却、
  并发去重（同 ID 只查一次）、每 IP 60/min 限速，防整群浏览打爆 VRChat 额度。
- **前端 group.js**：无头像兜底由死链改为 `/api/avatar/user?u=...`；DB 中的
  `assets.amlcdn.com` 历史缩略图 URL 不再直连（国内不可达），统一改走后端按 ID 解析。
- **前端 map.js**：`mapAvatarSrc(url, uid)` 支持按 ID 兜底，地图标记/世界列表头像同步受益。
- **server.js**：avatar 路由挂载时传入 `authState`（系统 VRChat 会话）。
- 路由清单基线（fixtures/route-inventory.json）同步 +1（GET /api/avatar/user）。
- 新增 5 条头像链路回归断言；全量 789 项测试通过。
- 提示：若系统 VRChat 账号未登录，`/api/avatar/user` 会回退占位图（解析需鉴权）；
  登录系统账号后即恢复。进阶用户仍可在「媒体代理源池」配置国内可达镜像加速回源。

## 2026-10-05 · VRChat 同步成功后弹"服务器内部错误"修复

用户实测：群组页点「同步 VRChat」→ 同步完成（成功 toast）→ 立即弹出"服务器内部错误"。
上传截图经 OCR 识别为服务器日志，定位根因（单一错误，全链路同源）：

```
[ERROR] groups: presence/contribute 服务端异常
Incorrect datetime value: '2026-09-03T14:48:42.963Z' for column 'last_login' at row 1
  at groups_members_sync.js:431:22
```

- **根因**：`/api/group/presence/contribute`（群友互助上报）把 **VRChat API 原样返回的
  UTC ISO8601 时间字符串**（`2026-09-03T14:48:42.963Z`）直接写入 `group_presence_share.last_login`
  （`DATETIME` 列）→ MySQL 严格模式抛 `Incorrect datetime value` → 500。
  同步成功后前端 `loadGroupMembers()` 内部会自动触发 `contributePresence()`，
  `api()` 对 5xx 先弹通用"服务器内部错误"再抛错，于是恰好出现在"同步好了之后"。
- **修复**：
  - `server/utils.js` 新增 `toSqlDatetime()`：把 VRChat ISO8601（带毫秒+Z / 无秒）
    规范化为 `YYYY-MM-DD HH:MM:SS`；Date 对象原样返回；坏值返回 `null`（写空比写坏值安全）。
  - `groups_members_sync.js` presence/contribute 的 `last_login` 入库前经 `toSqlDatetime`。
  - `events.js` `/sync-vrchat` 的 `event_time`（`evt.scheduledAt` 同样是 ISO8601）
    入库前经 `toSqlDatetime` —— 同款潜在 500，一并消除。
  - 前端 `api()` 新增 `opt.silent`（5xx 不弹全局 toast、仍抛错），
    `group.js` 的 `contributePresence()` 改为 `silent: true` —— 后台副链路失败
    不再打断用户主流程，即使上游再出问题也不至于把"服务器内部错误"糊到脸上。
- 新增 `toSqlDatetime` 黄金用例 6 条（含本次事故中实测的 `'2026-09-03T14:48:42.963Z'`）。
- 全部 784 项自动化测试通过。

## 2026-10-05 · 后台系统 VRChat 账号登录误踢超管修复

用户实测：后台登录系统 VRChat 账号 → 右下角弹"登录状态已失效"→ 1.5s 后被强制登出。

- **根因**：`routes/vrc_system.js` 的 `/login`（VRChat 账号密码校验失败）返回 401 时
  **没带业务错误码**；`/2fa`（验证码错误）返回 401 时带的是 `ErrorCodes.UNAUTHORIZED`
  （同样不在前端 `VRC_BUSINESS_CODES` 白名单内）。前端 `api()` 401 拦截器在
  `currentUser` 已登录（超管在场）时，把"VRChat 那边没通过"误判成"本站会话过期"
  → toast `session_expired` + 强制登出。
- **修复**：两处 401 均改为 `fail(res,401,...,{code:ErrorCodes.VRC_AUTH_FAILED})`，
  前端据此只弹真实原因、不再踢人。新增回归测试
  `system VRChat login/2FA 401 carry VRC_AUTH_FAILED code`。
- **配套加固**：VRChat 验证码输入框（登录/绑定/弹窗/后台 2FA 共 4 个）增加
  「仅数字+连字符、限长 10」输入过滤，防御浏览器自动填充/输入法把数字串拼乱
  （用户反馈偶发"数字倒序"）。经排查无 `direction:rtl`/`reverse()` 等代码层原因。
- 全部 778 项自动化测试通过。

## 2026-10-05 · VRChat 全链路缺陷清扫（对照 VRCX 源码逐项审计）

对照 VRCX（GitHub 开源客户端）源码 `src/stores/auth.js` / `Dotnet/WebApi.cs`
逐项核对了登录/2FA/头像请求的实现，确认：登录端点、Basic Auth 的 URL-encode+base64
编码、2FA 验证端点、邮箱验证码触发机制与 VRCX 完全一致。审计发现的缺陷本轮修复：

- **重复错误提示**：`api()` 401/403 拦截器已对 `VRC_BUSINESS_CODES` 内业务码 toast，
  但 `sendVrcLoginCode`/`doVrcLoginConfirm` 的 else 分支又补一次 toast →
  "Invalid Username/Email or Password" 弹两遍。修复：调用方命中 `VRC_BUSINESS_CODES`
  时不再重复提示（`public/js/auth.js`）。
- **429 误报"网络错误"**：`isApiHandledError` 未识别 `VRC_RATE_LIMITED`，调用方 catch
  再弹"网络错误: VRC_RATE_LIMITED"；且 429 拦截只读 `d.detail`，2FA 锁定（`fail()`
  的 `{error:'字符串'}` 形态）被误显示成泛化"限流"。修复：`isApiHandledError`
  纳入 `VRC_RATE_LIMITED`，429 分支回退读 `d.error`（`public/js/core.js`）。
- **`/config` 预热失败连带登录 500**：`vrchatBasicLogin` 登录前直接 await `/config`，
  VRChat 抽风/排队超时 → 整个登录 500。VRCX 登录前并不调用 `/config`。
  修复：预热改 try/catch 忽略失败，登录照常进行（`server/vrc.js`）。
- **登录网络异常抛 500**：`/auth/user` 请求超时/连接重置直接 throw → `handleError` 500。
  修复：转成带文案的 502（"连接 VRChat 服务器失败，请稍后重试"）由调用方统一提示。
- **前后端错误码不同步**：前端 `VRC_BUSINESS_CODES` 有 `ACCOUNT_PENDING`，后端
  `ErrorCodes` 缺该常量（代码里写字符串字面量），`round3-regressions.test.js` 白名单
  校验失败。修复：`server/utils.js` 补 `ACCOUNT_PENDING`，两处业务引用改为
  `ErrorCodes.ACCOUNT_PENDING`，并补齐 `auth-services.test.js` 的 `utils` mock。
- 全部 777 项自动化测试通过。

## 2026-10-05 · VRChat 绑定/登录误踢回登录页修复 + 登录页头像预览

- **VRChat 绑定 / 登录误判"会话过期"弹回登录页**：`/auth/vrchat-login`、
  `/auth/vrchat-bind-verify`、`/auth/vrchat-2fa` 在「VRChat 密码/验证码校验失败、
  账号未绑定、账户待审核」等场景统一返回 401，但这些 401 没带业务码 `code`，
  前端 `core.js` 的 401 拦截器把无 `code` 的 401 一律当作「本站会话过期」→
  弹"会话已过期"→ 1.5s 后强制登出跳回登录页（用户看到的"还没发验证码呢就弹回登录"）。
  - 后端 `server/auth_vrc_service.js` 7 处 401 增加
    `{ code: ErrorCodes.VRC_AUTH_FAILED }`（新增于 `server/utils.js` `ErrorCodes`）；
  - 前端 `public/js/core.js` `VRC_BUSINESS_CODES` 注册
    `VRC_AUTH_FAILED` 与 `ACCOUNT_PENDING`，401 命中即按业务错误交给调用方
    （弹出真实原因/引导绑定），不再触发登出。
- **登录页头像预览**：`previewLoginAvatar()` 早已存在但没有任何事件触发
  （仅恢复记住账号时调用），导致头像区永不显示。现按需求在
  `public/js/main.js` `bindEvents()` 中绑定：**输入账号后点击密码框（focus）**时
  按已填账号预览「本地头像 + VRChat 头像」。
- **VRChat 密码登录被拒「Invalid Username/Email or Password」**：
  VRChat 官方要求所有 API 请求带 `X-Client-Identifier` 客户端标识、
  `User-Agent` 须为「应用名_版本号」下划线格式；此前请求缺少该头且 UA 用了
  斜杠格式，可能被 VRChat 当作异常第三方客户端一律拒登。
  已为 `server/vrc.js` 登录与通用请求、`server/vrc_pipeline.js` 握手补充
  `X-Client-Identifier`（默认 `jingtuweb_1.3.0`，可经环境变量 `VRC_CLIENT_ID`
  覆盖），UA 默认值改为 `JingTuWeb_1.3.0`。

## 2026-10-03 · VRChat API 实测（连通性/风险/选型结论）

- 实测链路全部通过：上游 `api.vrchat.cloud/api/1/config` → HTTP 200；项目 `server/vrc.js` 封装层

- 风险结论：政策红线（Tupper Policy：禁 avatar ripping/客户端修改/自动化刷接口）、接口随时破坏性变更、
  账号风控、cookie 隐私均已由内置 40/min 限流、moderation 仅人工触发、写操作限本人绑定 cookie 覆盖。
- 选型结论：**代码层维持手写 `server/vrc.js`**（限流/安全/多账号定制均在），**参考层用官方 OpenAPI**
  （`ai-scratch/vrcapi-spec/` 作权威说明书）；不建议引入官方 npm SDK（会丢失限流与安全层）。
