## 2026-10-03 · 群聊功能完善：群解散 + 消息撤回 + 屏幕共享音频

- **群主解散群组**（修复「群主删不掉自己的群组」BUG）：
  - 新增 `DELETE /api/chat/groups/:groupId`（仅群主可调），事务内显式清理
    `chat_group_message_reads / chat_group_messages / chat_group_members / chat_groups`，
    并向成员广播 `group:dissolved` 后失效成员缓存。
  - 群设置弹窗为群主新增「解散群组」危险按钮（二次确认）；收到 `group:dissolved` 时
    前端自动退出语音房、停止位置共享并关闭会话详情。
- **消息撤回**（修复「消息撤回不了」+ 权限规则）：
  - 群消息：普通成员仅可撤回**自己 10 分钟内**发送的消息；群主/管理员可随时撤回任意成员消息。
    后端 `DELETE /api/chat/groups/:groupId/messages/:msgId` 增加 10 分钟窗口校验并广播
    `group:recalled`，全群实时移除。
  - 私聊消息：发送者仅可撤回 10 分钟内发送的消息，撤回后 `chat:recalled` 通知对端实时标记。
  - 前端消息气泡新增「撤回」按钮（按角色/时间窗控制可见性），撤回后显示「该消息已撤回」占位；
    群列表最后一条预览同步过滤已撤回消息。
- **屏幕共享系统音频**：`getDisplayMedia` 由 `{ video: true }` 升级为 `{ video: true, audio: true }`，
  私聊与群语音房在共享时把系统/标签页音频轨 `addTrack` 到对端连接，停止共享时 `removeTrack` 并重协商；
  浏览器选择器勾选「分享音频」即生效（Windows/ChromeOS 支持系统音频；macOS 需 Chrome 141+；
  Linux/Firefox/Safari 无系统音频时自动降级为仅画面）。
- 新增 i18n 文案（zh/en/ru/ja/fr/de 六语言）：撤回、已撤回、该消息已撤回、解散群组/确认/提示等。
- 测试与快照：新增 1 条路由后 `route-inventory.json` 同步为 **475 条**；顺带修正
  `security-regressions.test.js` 中过时的 `gm.created_at` 断言（实际列名为 `joined_at`）。

## 2026-10-03 · 运维面板按需启动 + 空闲自动关闭

- 站点管理后台「运维面板」改为**按需拉起**：点击按钮 → `POST /api/ops/start` 确保面板进程就绪后
  再新开 `/ops/` 窗口（不再要求面板常驻，避免入口 502 白屏）。
- 新增生命周期管理（`server/panel_proxy.js`）：`GET /api/ops/status` 查询运行/空闲状态；
  每次 `/ops` 代理访问刷新最后活动时间；空闲超过 `PANEL_IDLE_MINUTES`（默认 **20 分钟**）自动关闭
  面板进程（Windows `taskkill` / POSIX `SIGTERM`），下次点击入口再自动拉起。
- 面板页面打开期间每 3 分钟心跳保活（经 `/ops` 代理 ping `/api/bootstrap`），页面开着不会被误关；
  关闭页面后心跳停止，20 分钟后回收进程。
- 生命周期参数可调：`PANEL_IDLE_MINUTES`、`PANEL_IDLE_CHECK_SECONDS`、`PANEL_START_POLL_MS`
  （默认 20 分钟 / 60 秒 / 1000ms），便于部署调参与测试。
- 新增生命周期测试 `server/__tests__/panel-lifecycle.test.js`（5 例，真实定时器毫秒级快测）；
  路由快照 `route-inventory.json` 同步纳入 2 条新路由（共 474 条）。

## 2026-10-03 · VRChat API 实测（连通性/风险/选型结论）

- 实测链路全部通过：上游 `api.vrchat.cloud/api/1/config` → HTTP 200；项目 `server/vrc.js` 封装层
  `/config`、`/time` → 均 200；本地 `/api/health` → 200；`/api/vrc-monitor` 未登录 → 401（守卫正常）。
- 风险结论：政策红线（Tupper Policy：禁 avatar ripping/客户端修改/自动化刷接口）、接口随时破坏性变更、
  账号风控、cookie 隐私均已由内置 40/min 限流、moderation 仅人工触发、写操作限本人绑定 cookie 覆盖。
- 选型结论：**代码层维持手写 `server/vrc.js`**（限流/安全/多账号定制均在），**参考层用官方 OpenAPI**
  （`ai-scratch/vrcapi-spec/` 作权威说明书）；不建议引入官方 npm SDK（会丢失限流与安全层）。

## 2026-10-03 · Docker 方案审查修复

- 修复数据丢失风险：`server/data`（激活码文件 + SQLite 模式库）此前不在卷中、容器重建即丢失；
  现两个 compose 均挂载 `data:/app/server/data` 具名卷，Dockerfile 同步补 `VOLUME` 声明。

  无需手改 compose（体验默认值保持零前置一键）。
- db 健康检查改为读取容器内 `$$MYSQL_ROOT_PASSWORD`（兼容密钥覆盖）；两 compose 的
  `start_period` 统一为 120s；app/db 增加日志轮转（单文件 ≤50m、保留 5 份）。
- 同步更新 `docker.env.example`、`DEPLOY.md`、`docs/01-快速开始.md` 的持久化/覆盖说明。
