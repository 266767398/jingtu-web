## 一、整体架构概览

境途同游采用 **双轨登录体系**，核心设计原则：

> **必须先完成本地账号登录 → 绑定 VRChat 账号 → 之后才能使用 VRChat 快捷登录**

```
┌─────────────────────────────────────────────────────┐
│                    登录界面                          │
│  ┌──────────┐  ┌──────────┐  ┌──────────┐         │
│  │ 账号密码 │  │ VRChat   │  │ 初始化   │         │
│  │  登录    │  │  快捷登录 │  │ (仅首次) │         │
│  └────┬─────┘  └────┬─────┘  └──────────┘         │
│       │             │                              │
│       ▼             ▼                              │
│  ┌──────────────────────────────────┐             │
│  │     users 本地账号体系（核心）       │             │
│  │  login_id + password_hash         │             │
│  │  vrchat_id 绑定字段（可选）         │             │
│  └──────────────────────────────────┘             │
└─────────────────────────────────────────────────────┘
```

## 二、三种登录方式详解

### 1. 账号密码登录（主要方式）

**这是系统的主要登录方式，所有用户必须通过此方式登录。**

| 项目 | 说明 |
|------|------|
| API 端点 | `POST /api/auth/login` |
| 参数 | `loginId`（登录ID或显示名）、`password`（密码） |
| 会话机制 | Session Cookie (`connect.sid`) |
| 适用场景 | 所有已注册用户 |

**流程步骤：**

```
1. 用户输入登录ID + 密码
2. 后端查找 users 表（匹配 login_id 或 display_name）
3. 检查账户状态：
   ├── 是否被封禁 (banned)
   ├── 是否待审核 (approved)
   ├── 是否被锁定 (locked_until)
   └── 是否有密码 (password_hash)
4. 使用 bcrypt 验证密码
5. 成功 → 生成 Session → 返回用户信息
6. 失败 → 记录失败次数（5次后锁定15分钟）
```

### 2. VRChat 快捷登录（需先绑定）

**VRChat 登录仅适用于已绑定 VRChat 账号的用户。**

| 项目 | 说明 |
|------|------|
| API 端点 | `POST /api/auth/vrchat-login` |
| 前提条件 | 用户已通过本地账号登录，并在个人中心绑定了 VRChat 账号 |
| 两步验证 | 支持 VRChat 2FA（邮箱验证码 / Authenticator） |

**流程步骤：**

```
1. 用户输入 VRChat 用户名 + 密码
2. 后端调用 VRChat API 验证凭证
3. 根据 VRChat ID 查询 users.vrchat_id 字段
   ├── 未绑定 → 返回 401 + needBind: true → 前端显示绑定引导弹窗
   └── 已绑定 → 继续验证
4. 检查账户状态（封禁/审核/锁定）
5. 若需要 2FA → 发送验证码 → 用户输入验证码 → 完成登录
6. 若无需 2FA → 直接完成登录
7. 登录成功 → 更新用户 VRChat 信息 → 返回 Session
```

**未绑定时的引导弹窗：**

当用户尝试 VRChat 登录但未绑定时，系统会弹出引导弹窗：

```
┌──────────────────────────────────┐
│  🔐                               │
│  VRChat 账号未绑定                │
│                                  │
│  您的 VRChat 账号 [用户名]        │
│  尚未绑定本站账号                 │
│                                  │
│  1. 先使用 账号密码 登录本站      │
│  2. 登录后进入 个人中心 → VRChat绑定│
│  3. 绑定完成后即可使用 VRChat 登录 │
│                                  │
│  [切换到账号登录]  [我知道了]      │
└──────────────────────────────────┘
```

## 三、账号创建与 VRChat 绑定流程

### 3.1 账号创建

```
方式一：系统初始化 → 创建第一个超级管理员
    POST /api/auth/init
    参数: loginId, password, displayName
    
方式二：管理员创建（推荐）
    POST /api/users (需 super_admin 权限)
    参数: loginId, password, displayName, role, email
```

> ⚠️ **系统默认关闭自助注册**（`allow_register = 0`），所有账号由管理员创建。

### 3.2 VRChat 绑定

```
前置条件：用户已通过本地账号登录

1. 进入"个人中心" → 点击"绑定 VRChat"
2. 输入 VRChat 用户名 + 密码
3. 后端验证 VRChat 凭证
   ├── 如需要 2FA → 发送验证码
   └── 验证通过 → 检查是否已被其他账号绑定
4. 更新 users 表：
   ├── vrchat_id = VRChat 用户ID
   ├── vrchat_name = VRChat 显示名
   ├── vrchat_avatar_url = 头像URL
   └── avatar_type = 'vrchat'
5. 检查群组成员身份（自动验证）
6. 绑定成功 → 可使用 VRChat 快捷登录
```

**API 端点：**
- `POST /api/auth/vrchat-bind-verify` — 验证并绑定
- `POST /api/auth/vrchat-unbind` — 解绑

**后端文件：**
- [auth.js](file:///D:/phpstudy_pro/WWW/jingtu-web/server/routes/auth.js#L534) — `POST /vrchat-bind-verify` 路由

## 四、数据库表结构

### users 表（核心用户表）

```sql
CREATE TABLE users (
  id INT AUTO_INCREMENT PRIMARY KEY,
  login_id VARCHAR(50) NOT NULL UNIQUE COMMENT '登录ID',
  display_name VARCHAR(100) NOT NULL COMMENT '显示名',
  vrchat_id VARCHAR(100) UNIQUE COMMENT 'VRChat用户ID（绑定标识）',
  vrchat_name VARCHAR(100) COMMENT 'VRChat显示名',
  password_hash VARCHAR(255) COMMENT 'bcrypt密码哈希',
  role ENUM('super_admin','admin','member') DEFAULT 'member',
  vrchat_verified TINYINT DEFAULT 0 COMMENT '是否通过群组成员验证',
  avatar_type ENUM('vrchat','custom','none') DEFAULT 'none',
  custom_avatar_path VARCHAR(255),
  vrchat_avatar_url VARCHAR(500),
  -- 安全字段
  approved TINYINT DEFAULT 0 COMMENT '账户审核状态',
  banned TINYINT DEFAULT 0 COMMENT '封禁状态',
  failed_login_attempts INT DEFAULT 0 COMMENT '连续登录失败次数',
  locked_until DATETIME NULL COMMENT '账户锁定截止时间',
  -- 签到成就（V7.00）
  total_checkins INT DEFAULT 0,
  current_streak INT DEFAULT 0,
  max_streak INT DEFAULT 0,
  checkin_points INT DEFAULT 0,
  last_checkin_date DATE NULL,
  achievement_points INT DEFAULT 0,
  created_at DATETIME DEFAULT CURRENT_TIMESTAMP,
  updated_at DATETIME DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;
```

### 关键字段说明

| 字段 | 说明 | 登录流程中的作用 |
|------|------|-----------------|
| `login_id` | 本地登录ID | 账号密码登录的主要标识 |
| `password_hash` | 加密密码 | 验证密码正确性 |
| `vrchat_id` | VRChat 用户ID | VRChat 登录的匹配字段 |
| `approved` | 审核状态 | 未审核用户无法登录 |
| `banned` | 封禁状态 | 被封禁用户无法登录 |
| `locked_until` | 锁定截止时间 | 连续5次失败后锁定15分钟 |

## 五、安全机制

### 5.1 账户锁定策略

```
连续登录失败 5 次 → 账户锁定 15 分钟
锁定期间尝试登录 → 返回 423 + 剩余锁定时间
15 分钟后自动解锁 → 失败计数清零
```

### 5.2 密码安全

```
密码使用 bcrypt 加密存储
密码强度要求：大小写字母 + 数字 + 符号，至少 8 位
密码修改需验证旧密码
```

### 5.3 会话管理

```
使用 express-session + express-mysql-session 存储会话
Session Cookie：httpOnly + sameSite: lax
登出时彻底销毁会话
```

### 5.4 VRChat 绑定安全

```
绑定需验证 VRChat 凭证（用户名+密码+2FA）
同一 VRChat ID 只能绑定一个本站账号
同一本站账号只能绑定一个 VRChat ID
绑定的 VRChat Cookie 加密存储在 Session 中
```

## 六、常见问题

### Q1：为什么我不能直接用 VRChat 登录？

**A：** 这是系统的安全设计。VRChat 登录需要绑定到一个已存在的本站账号。请先使用账号密码登录，然后在个人中心绑定 VRChat 账号。

### Q2：如何创建新用户？

**A：** 系统默认关闭自助注册。请联系管理员创建账号。管理员可在"管理面板 → 用户管理"中创建新用户。

### Q3：忘记密码怎么办？

**A：** 密码重置已支持邮箱验证码三步流程（由 `mailer.js` + SMTP 发送；链接 `APP_URL` 默认 `localhost:3000`，生产须设为真实域名）。若 SMTP 未配置或邮件发送失败，仍可由超级管理员在后台重置。

### Q4：绑定的 VRChat 账号可以更换吗？

**A：** 可以。在"个人中心 → VRChat绑定"中先解绑当前账号，再绑定新的 VRChat 账号。

### Q5：被锁定的账户如何解锁？

**A：** 等待 15 分钟自动解锁，或联系管理员手动解锁。
