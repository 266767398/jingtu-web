# 网页版运维后台使用说明

> 境途同游 · 网页版运维控制台（替代交互式 `start-services.ps1`）
> 版本：v1.4.0 · 面板端口 3457 · 最后更新 2026-08-25

## 一、定位

网页版运维后台是一套**独立的 Node.js 服务**，用于在浏览器中管理境途同游站点的服务启停、数据备份、日志、网站用户与配置。它逐步替代原交互式 PowerShell 脚本 `start-services.ps1`（27 项功能）。

## 二、目录结构

```
jingtu-web/
├── start-panel.bat           # 启动器（薄壳，转调 PowerShell 主程序；双击进交互菜单 1-9 / O / R / 0；也支持 start / stop / restart / panel-start / panel-stop / panel-restart / status / start-all / stop-all / restart-all 参数）
├── start-panel.ps1           # 控制台主程序（PowerShell + UTF-8 BOM，彻底解决 cmd 中文乱码）
├── panel/
│   ├── panel-server.js      # Node HTTP 服务（端口 3457，仅 127.0.0.1）
│   ├── panel-api.ps1        # PowerShell 执行层（UTF-8 BOM，-Action 参数返回单行 JSON）
│   ├── panel-auth.json      # 面板密码（PBKDF2 哈希），删除后可重置
│   ├── panel-settings.json  # 面板设置（端口/局域网开关/令牌有效期）
│   └── public/index.html    # 单文件 Web UI（深紫主题，与站点一致）
```

## 三、启动与关闭

| 操作 | 命令 |
|---|---|
| 启动面板 | `start-panel.bat` 或 `start-panel.bat start` |
| 关闭面板 | `start-panel.bat stop` |
| 查看状态 | `start-panel.bat status` |

- 双击运行（不带参数）进入交互菜单：`1` 开启、`2` 关闭、`3` 状态、`0` 退出。
- 启动后浏览器自动打开 `http://localhost:3457`。
- 首次使用需设置**面板管理密码**（≥8 位），仅用于登录此后台，与网站账号无关。
- 关闭面板 = 终止监听 3457 的 `panel-server.js` 进程。

## 四、鉴权与安全

- 密码以 **PBKDF2**（10 万次迭代，16 字节随机盐）存储于 `panel/panel-auth.json`。
- 登录后发内存令牌（默认 12 小时滑动过期）；**连续 5 次失败锁定 15 分钟**。
- 面板默认**仅监听 127.0.0.1**；如需局域网访问，在「安全配置」页开启并重启面板。
- 高危操作（清空数据、恢复、释放端口、重置超管）均有**确认短语**双重校验。
- **忘记面板密码**：停止面板，删除 `panel/panel-auth.json`，重新启动面板即可重新初始化。

## 六、后端接口（`panel-server.js`）

### 认证类（无需 token）
- `GET /api/bootstrap` — 初始化状态
- `POST /api/init` — 首次设置密码
- `POST /api/login` / `POST /api/logout`

### 状态与服务（需 Bearer token）
- `GET /api/status` — 服务状态 + 磁盘 + IP + 权限
- `POST /api/service` — `{action:start|stop|restart, name}`

### 网站管理（需 token，直连 MySQL）
- `GET /api/site/overview` — 版本、用户数、活动数、动态数、群成员数
- `GET /api/site/users?page=&size=&kw=` — 用户列表（分页 + 搜索）
- `POST /api/site/user/toggle` — `{id, banned}` 禁用/启用
- `POST /api/site/user/reset-password` — `{id, password}` 重置密码
- `GET /api/site/config` — MySQL 配置（密码脱敏）+ panel-config.json

### 激活码管理（需 token，离线文件存储）
- `GET /api/activation-codes` — 激活码清单（`{total, used, unused, revoked, expired, codes}`；响应 `Cache-Control: no-store`，未使用码等同凭据不缓存）
- `POST /api/activation-codes/generate` — `{count(1-200), note?, expiresDays?(0-3650，0=永久)}` 生成注册激活码
- `POST /api/activation-codes/revoke` — `{code, reason?}` 作废激活码

> 面板激活码与主站 `/api/admin/activation-codes/*` 共用同一离线存储文件（默认 `server/data/activation-codes.json`，可用环境变量 `ACTIVATION_CODES_FILE` 覆盖），任一端生成/作废对另一端即时生效。前端交互详见 `panel/public/index.html` 的 `renderActivation`。

### 备份 / 日志 / 工具 / 安全 / 审计
- `POST /api/backup`、`GET /api/backups`、`POST /api/restore`、`POST /api/clear-data`、`GET /api/backup/download`
- `GET /api/logs/recent`、`POST /api/logs/search`、`POST /api/logs/clear`、`GET /api/audit-log`
- `GET /api/env/check`、`POST /api/export-config`、`POST /api/export-panel-config`、`GET /api/ports`、`POST /api/ports/kill`、`GET /api/disk`、`GET /api/lan-ip`、`POST /api/cache-clean`、`POST /api/export-site`
- `POST /api/change-password`、`POST /api/reset-superadmin`、`POST /api/settings`、`POST /api/reset-init`
- `POST /api/open-dir`、`POST /api/open-logs`、`POST /api/open-site`、`GET /api/task/:id`

### PowerShell 执行层（`panel-api.ps1`）

无状态执行层，`-Action` 参数返回单行 JSON。Action 清单：

`status` / `start` / `stop` / `restart` / `backup` / `backups` / `restore` / `clear-data` / `recent-log` / `search-log` / `clear-logs` / `check-env` / `export-config` / `export-panel-config` / `ports` / `kill-port` / `lan-ip` / `disk` / `cache-clean` / `audit-log` / `reset-superadmin` / `export-site` / **`reset`**（新增：重置初始化）

## 八、已知限制

1. **功能 #23「简易服务守护」未落地**：原脚本用会话内 `Start-Job` 实现，网页版 PS 执行层是无状态的一次性调用，无法维持后台守护进程。后续可用 Node 定时器或 Windows 计划任务替代。
2. **网站管理模块依赖 MySQL 在线**：`/api/site/*` 直连 `.env` 配置的 MySQL，若 MySQL 未启动将返回读取异常提示。
3. **面板密码与网站账号独立**：两者互不通用。

## 九、故障排查

| 现象 | 处理 |
|---|---|
| 面板启动报 `EADDRINUSE` | 端口 3457 被占用：`start-panel.bat stop` 后重试 |
| 忘记面板密码 | 停止面板 → 删除 `panel/panel-auth.json` → 重启重新初始化 |
| 网站管理页数据库读取异常 | 先在「服务管理」启动 MySQL |
| PS 脚本中文乱码 | 确认 `panel-api.ps1` 为 UTF-8 with BOM（`panel-server.js` 启动时自动补 BOM） |
| **启动控制台中文乱码（旧版 bat）** | 旧 `start-panel.bat` 在 cmd 下中文显示乱码；本仓库已切换为 **PowerShell 版控制台**（`start-panel.bat` 仅作薄壳调用 `start-panel.ps1`），彻底解决乱码。详见下文"控制台乱码修复"。 |

## 十、控制台乱码修复（PowerShell 版控制台）

**背景**：原 `start-panel.bat` 在 Windows cmd 中直接输出中文时受代码页（中文系统默认 936/GBK）与 cmd 字体字形影响，常出现"澶江?插 EB"之类的乱码。即便 bat 内加 `chcp 65001`，cmd 对 UTF-8 中文仍可能字形缺失；改回 936 又会让现代 UTF-8 脚本内的中文乱码，无法两全。

**方案**：保留 `start-panel.bat` 调用接口与文件位置不变（兼容所有脚本/定时任务），但内部仅作"薄壳"，把控制台渲染工作交给 `start-panel.ps1`（PowerShell 5.1+，UTF-8 with BOM）。

```
start-panel.bat  ──(cmd 调用)──▶  powershell.exe  ──▶  start-panel.ps1
    薄壳（纯ASCII）              PS宿主按BOM解析          主程序
```

**⚠️ BOM 是必须的（关键修复）**：`start-panel.bat` 必须以 **UTF-8 with BOM** 保存。原因：cmd 经典控制台默认代码页是 936/GBK；如果 bat 是"UTF-8 无 BOM"，cmd 会用 GBK 把 bat 内的中文逐字节解读成乱码，再把乱码当命令执行，于是疯狂刷 `'XXX' 不是内部或外部命令`。加 BOM 后 cmd 会自动切到 UTF-8 解析，中文注释不再乱码。bat 顶部已改为纯 ASCII（连 `title` 都用英文），即便有人误存为"UTF-8 无 BOM"也不会再触发该问题。`start-panel.ps1` 同样带 UTF-8 BOM（PowerShell 5.1 解析中文函数体也需要它）。

- `start-panel.ps1` 顶部强制 `[Console]::OutputEncoding = UTF8` + `chcp 65001`，并 `[CmdletBinding()]` 风格定义函数，PS5.1 也能正确解析中文函数体与菜单文字。
- 控制台输出走 `.NET`（TCPClient / WebRequest / Start-Process），不再依赖 cmd 渲染。
- `netstat -ano` 端口→PID 解析改为**精确正则**（`127.0.0.1:PORT` / `0.0.0.0:PORT` + LISTENING），避免误把其它连接的 PID 抓过来。
- 内置 HTTP 探测对 MySQL(3306)/Nginx(80) 等非 HTTP 端口回退为 `TCP 端口可达`，不强行用 `Invoke-WebRequest`。

**接口兼容**：所有历史 `start-panel.bat start | stop | restart | status` 用法不变；新增 `panel-start | panel-stop | panel-restart | start-all | stop-all | restart-all`，分别对应"运维面板启停/全部启停"。

**交互菜单**（双击 `start-panel.bat` 或无参数调用时进入）：

```
[1] 启动网站         [2] 停止网站         [3] 重启网站
[4] 启动运维面板     [5] 停止运维面板     [6] 打开网站
[7] 重启运维面板     [8] 全部启动         [9] 全部停止
[O] 打开日志目录     [R] 刷新状态         [K] 清理卡死 cmd 窗口
[0] 退出
```

**窗口身份标识**：`start-panel.bat` 与 `start-panel.ps1` 启动后都会把**控制台窗口标题**设为 `境途WEB 运维控制台`，方便在多窗口并存时一眼区分本控制台与机器上其他 cmd 窗口（例如某些 IDE 的 MCP 后端在循环重试时也会弹出刷错信息的 cmd 窗口，**这些窗口与本控制台无关**）。

**清理卡死 cmd 窗口**：菜单按 `K` 或命令行 `start-panel.bat clean` 会**只关闭**那些：
- 不是本控制台、不是 IDE / 资源管理器 / Windows Terminal 拉起的
- 不是 MCP 后端、不是运维面板自身的
- 默认标题的 `cmd.exe` 子进程（`安全白名单`：explorer / Code.exe / code.exe / WindowsTerminal / wt / conhost / powershell / bash）

属于"白名单内的父进程"或"命令行带 npx / mcp-server / panel-server"的进程会**自动跳过**，不会误伤 IDE 或面板。

**日志**：启动 / 停止时把 stdout 与 stderr 重定向到 `logs/site.log` 与 `logs/panel.log`，可在菜单按 `O` 直接打开日志目录。

**零外部依赖**：仅依赖 `node.exe`（启动网站/面板时），环境变量未配置时通过 `C:\Program Files\nodejs\node.exe` 等常见路径兜底。
