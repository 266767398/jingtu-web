# 境途同游 Web 项目 — 前端架构详解

> 基于当前 `public/` 与 `server/` 源码核对  
> 最后更新：2026-09-02（V9.5 设计令牌熔铸 + 移动端响应式完善 + 缓存版本号统一刷新；V9.4 地图「VRChat 世界」面板新文件 `worlds-panel.css` 已纳入）

## 一、前端整体架构

### 1.1 架构模式与页面边界

主应用是一个**无前端路由器的 Tab 式单页入口**：

- `public/index.html` 预置登录层、主应用、各个 `tabpanel` 和模态框。
- `public/js/ui.js` 的 `switchTab(tab)` 通过增删 `.d-none` 切换内容，并调用相应模块的加载函数。
- 当前代码没有基于 URL hash、History API 或客户端路由库的页面路由；刷新不会按当前 Tab 恢复。
- 登录、资料、管理等多数功能位于 `index.html` 内，但不能据此称为“所有页面都在一个 HTML 中”。

当前独立页面：

| 页面 | 用途 |
|------|------|
| `public/index.html` | 主应用入口 |
| `public/setup.html` | 六步建站配置向导 |
| `public/migration.html` | 数据迁移工具 |
| `public/starting.html` | 本地启动等待/跳转页 |

`public/start-node.php` 是仅供本地开发使用的 PHP 启动辅助端点，不是主应用 SPA 页面。

页面底部脚本的实际声明顺序：

```text
core.js              （基础设施：api()/工具/i18n 引导）
ui.js                （switchTab/菜单/可访问性）
/vendor/gsap/gsap.min.js
/vendor/gsap/ScrollTrigger.min.js
motion.js            （GSAP 驱动动效）
reveal.js            （IntersectionObserver 滚动揭示）
nav-more.js / nav-scroller.js
i18n.js / theme.js / auth.js
loader.js            （路由模块懒加载器，包裹 switchTab）
smartsearch.js       （全局命令面板 VN-9）
init.js              （引导启动：initI18n/switchTab，须在 loader.js 之后）
main.js              （定时刷新 / WebSocket 生命周期）
```
> 功能路由模块（`members/home/group/announcements/events/vrc/geo/map/chat/album/管理脚本/posts/live/birthday/profile/profile-page/checkin/achievements/friends/follows/collections/admin-ui/admin-model-collections`，共 25 个）**不再由 `index.html` 逐行声明**，而是由 `loader.js` 在访问对应 Tab 时按需加载、并在浏览器空闲（`requestIdleCallback`，4 秒超时）时后台预载其余模块；懒加载脚本统一带 `?v=20260823e` 缓存破坏戳，与 Service Worker cache-first 配合。该重构（P1 性能优化）将首屏关键路径从“一次性 ~1.17MB 路由 JS”缩减为“仅当前 Tab 所需模块”。

上述核心脚本中 `core.js` 和 `ui.js` 没有 `defer`，其余外部脚本使用 `defer`。这些是非 ES Modules 的全局脚本；功能路由模块由 `loader.js` 动态插入 `<script async=false>` 按需加载（仍属全局脚本，非打包/代码分块）。`main.js` 最后声明，以便调用前面模块暴露的全局函数。

> 由于是全局脚本而非模块，**同名函数会被后加载的文件静默覆盖，且不产生任何报错**。
> 新增全局函数前请先确认其他文件没有同名定义，回归测试会扫描这一点。

### 1.3 模块关系

```text
core.js
  ├─ api()/apiForm()/uploadWithProgress()
  ├─ CSRF、Loading、toast、modal、转义与格式化工具
  └─ 被各业务脚本通过全局函数直接调用

i18n.js + languages/*.js
  ├─ __()/initI18n()/setLanguage()
  └─ 负责静态 data-i18n 与部分动态内容

ui.js
  ├─ switchTab()
  ├─ 桌面/移动 Tab 状态同步
  └─ 菜单、表单与可访问性增强

main.js
  ├─ init()
  ├─ 定时刷新
  └─ WebSocket 生命周期
```

当前代码依赖共享的 `window`/全局作用域和固定脚本顺序，没有打包器层面的模块隔离或代码分块。

### 1.4 主界面功能范围

桌面 Tab 以 `index.html` 为准，包含：首页、成员、群组、公告、活动、生日、相册、收藏夹、收藏馆、动态、直播、地图、聊天、通知、管理、好友、关注。其中“收藏馆 / 好友 / 关注”为 2026-08-23 前后新增的 Tab（`loader.js` 的 `TAB_MODULES` 已映射对应懒加载模块）。个人资料和用户资料也使用 `tabpanel`，但通过用户入口进入。

旧文档中的积分商城、排行榜、夸夸墙、投票、每日一题、挑战等脚本没有出现在当前 `public/js/` 的主入口加载链中，不能写作已实现的主界面功能。

## 二、CSS 与响应式体系

### 2.1 CSS 文件职责

| 文件 | 当前职责 |
|------|----------|
| `01-variables.css` | 颜色、间距、圆角等变量 |
| `02-base.css` | 重置、基础元素和工具样式 |
| `03-layout.css` | Header、容器、Tab、响应式布局 |
| `04-components.css` | 按钮、卡片、表单、模态框等组件 |
| `05-auth.css` | 登录区域 |
| `06-members.css` | 成员相关界面 |
| `07-profile.css` | 资料页 |
| `08-chat-posts.css` | 聊天与动态 |
| `ui-enhance.css` | 移动导航、表单、交互与可访问性增强 |
| `favorites.css` | 收藏夹 |

`achievements.css` 和 `checkin.css` 当前未从 `index.html` 或 `style.css` 加载。

### 2.2 主题系统

主题由 `theme.js` 管理，配置存入 `localStorage` 的 `jingtu_theme_config`。当前支持：

- `manual`：手动选择 `light`/`dark`；
- `auto`：跟随 `prefers-color-scheme`；
- `schedule`：按本地时间计算明暗，并每分钟重新应用；
- 自定义 `accentColor`，写入 `--accent`、`--accent2`、`--hover`。

`initTheme()` 在 `main.js` 初始化时调用。实现不是旧版单一 `toggleTheme()` 流程，也不使用旧文档示例中的 `--accent-color` 变量。

### 2.3 响应式与移动导航

响应式规则分散在布局和增强样式中，并非严格的“桌面三列、平板双列、移动单列”统一栅格。应按具体组件的 `@media` 规则理解。

当前移动端有两种导航补充：

1. `index.html` 中固定底栏，共 **7 个**入口：`home`、`events`、`live`、`posts`、`chat`、`admin`、`notifications`。其中管理入口仍受权限控制，聊天和通知可显示角标。
2. `ui.js` 的 `initMobileTabMenu()` 动态创建“更多功能”网格和遮罩，列表还包括成员、群组、公告、生日、相册、收藏、地图、个人资料等。

`switchTab()` 同时更新 `.tab`、`.tab-content` 和 `.mobile-tab-bar-item` 的状态。`mobileTabHit()` 调用 `HapticFeedback.impact('light')`；不要描述成函数内直接固定调用 `navigator.vibrate(20)`。

移动底栏不是“首页、成员、活动、聊天、管理”五项，且“成员”不在固定底栏。

### 2.4 可访问性

桌面 Tab 使用 `role="tab"`、`role="tabpanel"`、`aria-selected` 和 `tabindex`。`ui.js` 还包含用户菜单键盘导航、模态框焦点/ARIA、跳转链接等增强逻辑。动态生成界面仍需各业务模块正确提供标签，不能据此声称全站已经完整满足某项无障碍标准。

## 三、JavaScript 核心模块

### 3.1 `core.js` — API 与通用能力

| 能力 | 实际行为 |
|------|----------|
| `api(path, opt)` | `fetch` + `credentials: include`，JSON 请求，10 秒超时 |
| `ensureCsrf()` | 从 `/api/csrf-token` 取 Token；同一时刻去重，后续写请求前重新获取 |
| 写请求 | 自动附加 `X-CSRF-Token` |
| 错误处理 | 集中处理 401、403、429、5xx 和超时，并抛出约定错误 |
| `apiForm()` | FormData 上传，附加 CSRF；没有 `api()` 的 10 秒 AbortController |
| `uploadWithProgress()` | 基于 `XMLHttpRequest` 提供上传进度 |
| UI/安全工具 | Loading、toast、modal、确认框、HTML/属性转义、URL/日期工具 |

调用方仍负责解析 `Response`、处理业务错误和渲染数据。CSRF 不是永久本地缓存。

### 3.2 `main.js` — 启动、刷新与实时连接

`init()` 的当前流程：

1. 初始化登录粒子、i18n 和主题；
2. 请求 `GET /api/auth/init` 判断数据库是否无用户；
3. 无用户时显示 `index.html` 内的简化初始化登录模式；
4. 有用户时尝试自动登录，否则显示登录层；
5. 绑定全局事件；
6. 登录后启动交错刷新队列。

交错刷新在 30 秒后首次执行，此后每 75 秒轮换首页、成员、公告、活动和相册；页面隐藏时暂停，重新可见时立即恢复。它不是“每 5 分钟统一刷新通知和位置”。

`main.js` 不提供 hash/History 路由处理。Tab 切换由 `ui.js` 负责。

### 3.3 `ui.js` — Tab 与 UI 增强

`switchTab(tab)`：

- 清理相册、聊天位置或直播的部分离开态；
- 更新桌面 Tab 的 active/ARIA 状态；
- 隐藏其他 `tabpanel`，显示目标区域；
- 同步固定移动底栏；
- 更新标题并调用对应加载函数。

主要映射包括 `loadHome()`、`loadMembers()`、`loadEvents()`、`loadAlbum()`、`loadPosts()`、`loadLiveStreams()`、`loadFavoritesPage()`、`initMap()`、`loadChatConversations()`、`loadNotificationsForCenter()` 和管理模块加载函数。

### 3.4 认证与应用内初始化

`auth.js` 负责账号登录、登出、自动登录、VRChat 登录/2FA 和绑定引导。VRChat 未绑定时的前端引导由 `showVrcBindGuide()` 创建弹层。

`index.html`/`init.js` 中的“无用户初始化模式”与独立 `setup.html` 是两条不同入口：

- 应用内模式针对“数据库无用户”；
- 独立 Setup 以 `.env` 是否存在决定是否开放，负责完整环境配置。

两者不应合并描述为同一个三步或六步向导。

### 3.5 主要业务模块

| 模块 | 当前接线与职责 |
|------|----------------|
| `home.js` | 首页统计、活动和动态摘要 |
| `members.js` | 成员列表、筛选和成员卡片 |

## 四、数据与交互流程

### 4.1 Tab 导航

```text
桌面 Tab / 固定移动底栏 / 移动更多菜单
  → switchTab(tab)
  → 更新 active、ARIA 与标题
  → 隐藏其他 tab-content
  → 显示目标 tab-content
  → 调用目标模块加载函数
```

该流程不修改 URL，所以不具备传统 SPA 路由的深链接、前进/后退或按 URL 恢复状态能力。

### 4.2 数据加载

各业务模块直接调用 `api()`/`apiForm()`。加载策略并不完全统一：

- 部分页面使用 `Promise.all` 并行请求，例如收藏夹和聊天；
- 部分筛选在本地执行，部分会重新请求后端；
- 多处图片使用 `loading="lazy"`；
- 首页等模块会被 `main.js` 的交错定时器刷新；
- 不能概括为所有模块都有统一缓存、分页或请求合并层。

### 4.3 WebSocket

登录后的应用通过 `connectWebSocket()` 连接：

```text
http 页面  → ws://<host>/ws
https 页面 → wss://<host>/ws
```

当前前端行为：

- 每 25 秒发送 `{ type: "ping" }`；
- 最多重连 10 次；
- 采用 1 秒起、最高 30 秒的指数退避；
- 处理在线列表、新通知、位置、私聊和群聊消息；
- `chat.js` 发送消息时 WebSocket 优先，不可用时回退 HTTP。

服务端 `ws_service.js` 在升级阶段校验 Origin，并使用现有 Session Cookie 识别用户。不是无认证的独立 Token 通道。

### 4.4 API 与表单

普通业务 API 经 `core.js` 统一附带 Cookie 和 CSRF。独立 Setup 使用自己的 `fetch` 与超时逻辑，因为安装前不能依赖主应用会话。

不要假设所有表单都有同样的实时校验、错误文案或 30 秒超时：这些规则由各页面/模块分别实现。

## 五、移动端导航详解

### 5.1 固定底栏

`#mobileTabBar` 是 `index.html` 中的语义化 `<nav>`。七项顺序为：

```text
首页 → 活动 → 直播 → 动态 → 聊天 → 管理 → 通知
```

底栏用于高频入口，不等于完整功能列表。管理项由管理员可见性逻辑控制。

### 5.2 更多功能菜单

`initMobileTabMenu()` 动态创建：

- `.mobile-tab-overlay` 遮罩；
- `.mobile-tab-menu` 面板；
- 按 `TAB_ITEMS` 生成的功能网格；
- 触发菜单的按钮。

因此移动端访问其余功能依赖该菜单，而不是固定底栏中的“成员”按钮或一个通用 Header 汉堡导航。

### 5.3 状态与角标

固定底栏通过 `data-tab` 与 `switchTab()` 同步 active 状态。聊天和通知具有独立角标元素；公告、活动等桌面角标不代表固定底栏都有对应项。

## 六、主题与国际化

### 6.1 i18n 架构

主应用当前加载六种语言：

```text
zh, en, ja, fr, de, ru
```

语言表由 `languages/*.js` 挂到 `window._LANG_*`，`i18n.js` 负责读取。i18n **不在 `core.js` 中**。

核心 API：

| 函数 | 用途 |
|------|------|
| `__(key, replacements)` | 获取文本并替换参数 |
| `initI18n()` | 选择初始语言 |
| `setLanguage(lang)` | 保存语言并更新界面 |
| `applyStaticI18n()` | 更新 `[data-i18n]`、placeholder 等静态标记 |
| `reloadDynamicI18n()` | 按当前 Tab 重新加载部分动态内容 |
| `showLangSwitcher()` | 显示语言选择器 |

初始语言优先级为：URL `lang` 参数 → `localStorage.preferredLang` → 浏览器语言 → `zh`。

### 6.2 覆盖边界

`index.html` 大量使用 `data-i18n`，业务脚本也广泛调用 `__()`，但不能仅按语言文件键数宣称所有动态文案均已翻译。

独立 `setup.html`/`setup.js` 当前是中文硬编码，没有接入主应用的语言包和 `i18n.js`。因此 Setup 不是六语言向导，语言文件中即使存在 `setup.*` 键也不代表页面已使用。

**2026-08-16 补全状态**：已补齐所有被引用但缺失的翻译键。当前键数 zh=1397，en/ru/de/ja/fr 各 1380；5 个目标语言键集合完全一致、0 重复、0 缺失引用（zh 比目标语言多约 17 键，多为 `setup.*` 等 zh 专有、未被向导接入的键，非翻译缺口）。补全用本机 Ollama `qwen2.5:3b-instruct` 批量翻译、统一重建为 `"key": "value",` 双引号尾逗号格式。仍有约 41 个键因 3B 模型翻译能力局限保留中文回退（en 1 / de 1 / ja 31 / fr 8），建议人工校对（尤其日语）。综上：键集合层面已无被引用却缺失的键，但「键数齐全」不等于「动态文案 100% 已翻译」——上述中文回退键与 Setup 硬编码仍属待补。

主题系统与语言系统彼此独立：主题使用 `jingtu_theme_config`，语言使用 `preferredLang`。

## 七、建站 Setup 与独立页面

### 7.1 开放条件

`setup.html` 加载 `setup.js` 后请求 `GET /api/setup/check`。服务端以项目根目录 `.env` 是否存在作为配置状态；已配置时 Setup 的测试/保存接口拒绝继续操作。不能仅用 `/api/auth/init` 的用户数判断完整 Setup 是否开放。

### 7.2 六步流程

`setup.js` 的 `TOTAL_STEPS` 为 6：

1. 数据库配置，并调用 `POST /api/setup/test-db`；
2. 安全/站点配置；
3. 超级管理员；
4. 可选 VRChat 配置；
5. 可选 SMTP 配置，可调用 `POST /api/setup/test-email`；
6. 确认并一次性调用 `POST /api/setup/save`。

保存请求提交 `dbHost`、`adminUser`、`smtpHost` 等扁平字段。后端先写入 `.env`，再检查目标库中是否已有 `users` 表并创建超级管理员；它不会创建表，缺少 `users` 表或创建管理员失败时会删除刚写入的 `.env`。因此应先运行 `node db_init.js` 初始化表结构。这不是每步分别持久化。

### 7.3 其他独立页

- `migration.html` 是独立迁移界面，不由 `switchTab()` 管理。
- `starting.html` 只负责本地启动期间的提示/跳转。
- `start-node.php` 会尝试辅助启动本地服务，源码明确限定为开发用途，不应描述为生产部署机制。

## 八、签到、成就与收藏

### 8.1 签到前端：已接入（V7.10 起）

`public/js/checkin.js` 定义了 `CheckinModule`，请求：

- `GET /api/checkin/me/status`
- `POST /api/checkin/me/checkin`

接线方式：

- `checkin.js` 不再由 `index.html` 逐行声明，而是由 `loader.js` 按 Tab 懒加载（列入 `ROUTE_MODULES`，访问“我” Tab 时加载）；
- `style.css` 通过 `@import url('checkin.css')` 引入样式；
- **不使用 `DOMContentLoaded` 自启**，而是由 `auth.js` 的 `showApp()` 调用 `checkinModule.init()`，
  保证只在登录成功、主界面可见之后才初始化；
- 卡片插入位置是**个人中心 `#tab-me` 的末尾**，不是首页——首页已按"避免重复统计"的原则精简。

`server/routes/checkin.js` 的接口存在，不等于前端已接线。另有一套已接入 `events.js` 的"活动签到"界面，两者用途不同。

> 历史教训：本模块的后端路由、数据表、CSS、i18n 文案曾长期全部就绪，
> **唯独 `index.html` 少两行 `<script>`**，导致整套功能对用户完全不可见且不报任何错。
> 现已有回归测试（`round6-sync-regressions.test.js`）扫描
> "public/js 下不得存在任何 HTML 页面都没引用的脚本" 与
> "public/css 下没有既不被 `<link>` 也不被 `@import` 引用的样式表"。

### 8.2 成就前端：已接入（V7.10 起）

`public/js/achievements.js` 定义了 `AchievementsModule`，请求 `GET /api/achievements/me`，
接线方式与签到一致（`loader.js` 懒加载 `achievements.js` + `@import url('achievements.css')` +
由 `showApp()` 调用 `achievementsModule.init()` + 挂在 `#tab-me` 末尾）。

服务端此前的两个缺陷已修复：

- `/me`、`/me/type/:type`、`/me/unlocked`、`/me/locked` 四个端点读取 `user_achievements`
  时**均未按当前用户过滤**，任何登录用户都能读到全站所有人的成就进度（越权）；
- 查询以 `FROM user_achievements` 起手，导致尚未触发过任何成就的用户拿到空数组。
  现已改为从 `achievements` 表出发 `LEFT JOIN ... AND ua.user_id = ?`，
  新用户可正常看到全部锁定成就。详见 `docs/05-API接口全文档.md` 的成就小节。

### 8.3 收藏：已接入

收藏与前两者不同：

- `index.html` 有 `tab-favorites`；
- 加载了 `favorites.css` 和 `favorites.js`；
- `switchTab('favorites')` 调用 `loadFavoritesPage()`；
- 前端并行加载 World/Avatar 收藏，并提供搜索、添加/取消等操作。

因此收藏可描述为当前接入模块，但实际可用性仍依赖认证、VRChat 状态和服务端接口。

### 8.4 好友 / 关注 / 收藏馆：已接入（懒加载）

这三个新功能由 `loader.js` 的 `TAB_MODULES` 映射到懒加载模块，访问对应 Tab 时由 `switchTab` 包裹器按需加载：

- **好友**（`friends.js`，Tab `friends`）：好友申请 / 响应 / 拉黑 / 互关 / 共同好友，对接 `server/routes/friends.js`（`/api/friends`）。
- **关注**（`follows.js`，Tab `follows`）：关注 / 取关 / 粉丝 / 互关计算，对接 `/api/follows`。
- **收藏馆**（`collections.js`，Tab `collections`）：V8.2 统一收藏（收藏夹 + 收藏项 + 评分 + 失效检测），对接 `/api/collections`；合并原 model-collections 能力。

> 注意：`favorites.js`（旧“收藏夹” Tab）仍由 `switchTab('favorites')` 调用 `loadFavoritesPage()`，但**不在** `loader.js` 的 `ROUTE_MODULES` 列表中，也未出现在 `index.html` 急切脚本块中——若其加载路径未被其他脚本覆盖，可能成为新的“少两行 script”类接线缺口，建议回归测试 `round6-sync-regressions.test.js` 复核。

## 九、PWA 现状

`index.html` 引用了 `manifest.json`，仓库也有 `sw.js`，且**已注册启用**：`index.html` 在 `window load` 后调用 `navigator.serviceWorker.register('/sw.js')`（非安全上下文静默忽略，HTTPS/localhost 生效）。

当前能确认的事实：

- Manifest 提供名称、图标、启动 URL 和显示配置；
- `sw.js` 已注册：对带 `?v=` 版本号的 JS/CSS 采用 cache-first（版本号变即资源变、命中即返回），对同源非 API 请求采用网络优先、缓存兜底；
- `/api/` 请求明确不缓存；
- 预缓存仅含 `/`、主 CSS、Manifest 和四个图片，主 JS/语言包未进预缓存；HTTP 局域网访问由服务端 `Cache-Control: immutable` 兜底；
- 当前可确认“已注册 + 版本化资源 cache-first”，但不能保证完整离线（主 JS/语言包未预缓存）或已通过可安装性审核。

浏览器 Notification API 的使用与 PWA/Service Worker 启用是两回事。

## 十、性能与缓存事实

### 10.1 已有实现

| 项目 | 当前事实 |
|------|----------|
| 响应压缩 | Express 使用 `compression` 中间件 |
| 图片处理 | 多个上传路径使用 Sharp 缩放/压缩，部分生成缩略图 |
| 图片懒加载 | 主页面和动态模板多处使用 `loading="lazy"` |
| 并行请求 | 收藏、聊天等模块使用 `Promise.all` |
| 实时更新 | WebSocket 承担在线、通知、位置和聊天消息 |
| 后台降载 | 页面不可见时暂停 `main.js` 的交错刷新 |
| 脚本解析 | 大部分业务脚本声明为 `defer` |

### 10.2 不应宣称的优化

- Service Worker 现已由 `index.html` 注册启用（版本化资源 cache-first），可计入已启用的静态缓存；但仍非完整离线（主 JS/语言包未预缓存）。
- Express 主静态目录配置为 `maxAge: 0, etag: false`，不能概括为全站长缓存。
- 脚本虽使用 `defer`，但仍全部在主页面声明；没有按功能代码分割或按需下载。
- 没有源码测量数据支持“首屏目标小于 2 秒”或固定毫秒时间线。
- 并非所有模块都统一使用模块级缓存、分页或 `Promise.all`。
- `compression` 是传输压缩，不等同于构建期 CSS/JS minify。

### 10.3 缓存例外

服务端对部分专用资源/响应可能设置单独缓存头，应逐路由判断；不能把某个路由的策略推导为整个 `public/` 静态目录的策略。

## 十一、安全与运行边界

- 主应用 API 使用 Session Cookie；写请求经 CSRF Token。
- `api()` 默认 10 秒超时，CSRF 获取为 5 秒；不同模块或独立页面可有自己的超时。
- WebSocket 使用同一站点 Session，并在服务端升级阶段检查 Origin。
- 前端转义工具和 CSP 相关改造降低风险，但动态 HTML 仍要求业务模块正确调用 `esc()`/`escAttr()`。
- 管理 Tab 的隐藏只是界面控制，实际授权必须由服务端中间件和路由执行。

## 十二、滚动锁与弹窗可访问性

页面滚动锁由 `public/js/ui.js` 统一管理，任何新增的浮层都必须复用它，不要直接改写 `document.body.style.overflow`。

| 能力 | 实现 | 说明 |
|------|------|------|
| 引用计数滚动锁 | `lockBodyScroll(owner)` / `unlockBodyScroll(owner)` | 以 owner 去重；只有最后一个持有者释放时才恢复原始 `overflow`。当前持有者包括弹窗实例、`mobile-tab-menu`、`generic-lightbox`。 |
| 弹窗可见性判定 | `isModalOpen(el)` | 项目内同时存在 `.modal.show`（`.modal` 默认 `display:none`）与 `.d-none` 两套控制方式，必须经此函数判定，禁止只检查 `.d-none`。 |
| 弹窗栈 | `_modalStack` | 支持嵌套弹窗：关闭上层时焦点与键盘监听回落到下层，全部关闭后才解锁滚动。 |
| 焦点陷阱 | `handleModalKeydown` | 仅在存在真正打开的弹窗时拦截 Tab；无弹窗打开时不干预页面 Tab 顺序。 |
| 状态同步 | `initModalAccessibility()` | MutationObserver 监听 `class` 与 `style` 变化（`core.js` 的 `showModal()` 通过内联 `display` 打开弹窗），弹窗从 DOM 移除时同样释放锁。 |

> 历史缺陷：早期实现按 `.d-none` 判定可见性，导致页面加载时 68 个默认隐藏的 `.modal` 全被判为"已打开"，`body.overflow` 被永久锁死（整页无法滚动），且 Tab 被困在隐藏弹窗内（输入框之间无法切换）。回归测试见 `server/__tests__/ui-interaction.test.js`。

CSS 侧的配套约束（`public/css/ui-enhance.css` 末尾）：

- `.login-overlay` 与 `.modal` 均为 `overflow-y:auto`，内容超过视口时可滚动，避免小屏下按钮不可达。
- `html { overflow-y:auto }` 作为兜底；JS 的内联 `overflow` 优先级更高，不影响正常锁定。
- 统一 `:focus-visible` 轮廓、滚动条、选中色与禁用态；`@media (hover:none)` 下图标按钮最小点击区域 40px。
