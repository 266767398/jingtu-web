项目总览

DOC 02 · 定位 / 技术栈 / 目录 / 版本

定位

面向 VRChat 社群 的一体化单体 Web 应用：原生 HTML/CSS/JS 前端 + Node.js/Express 后端，同时提供静态文件、HTTP API 与 WebSocket。

  • 前端：无框架、无打包器，Tab 式单页
  • 后端：Express 单体，中间件主链串联
  • 存储：MySQL 默认，SQLite 单机模式可选
  • 实时：/ws 与 HTTP 共用 Server

技术栈

  • 后端：Node.js ≥20 · Express 4 · mysql2 · express-session(+mysql) · bcryptjs · ws · Multer/Sharp · node-schedule · Nodemailer
  • 前端：原生 JS/CSS · i18n 6 语言 · Leaflet(CDN) · PWA
  • 可选：Redis(缓存/限流/CSRF) · PM2 · Nginx/TLS · Docker Compose

版本

package.json 1.3.0；启动日志 V8.2。

  • MySQL 模式 93 张表（核心 87 + 归档/收藏/队伍/VRC 缓存等运行时表）
  • 历史文档已并入本文档体系，archive/ 已清理

升级 / 回滚

  • Docker：docker compose build && up -d；server/package.json 变更自动 npm ci
  • 宝塔/裸机：git pull --ff-only → npm ci && node db_init.js → pm2 restart
  • 在线更新（超管）：git fetch → ahead/behind 保护 → merge --ff-only → 可选自动重启（跨平台 WMI/helper，2~3 秒中断）
  • 更新绝不执行 git clean；.env / uploads / assets / server/data 均 .gitignore 内不受影响
  • 回滚：针对已标记版本 git revert（勿强制重置共享分支）

备份与恢复

  • 每日 02:30 自动备份（auto_ 前缀），数据库导出 + uploads/ 打包
  • 保留策略：FILE_RETENTION_DAYS（默认 90）/ BACKUP_RETENTION_DAYS（默认 7）
  • 手工备份：内置 /api/admin/backups/*（管理员 + CSRF），口令经 MYSQL_PWD 传参防 ps 泄露
  • 恢复前先停写流量并保留现网备份；恢复演练至少每月一次

入口与端口（本机 / 局域网双形态）

访问方地址路径
本机浏览器http://localhostNginx 80 反代 → Node 3456（规范本机入口）
本机浏览器http://localhost:3456Node 直连；页面导航 302 →80（API / 静态 / WS 不跳）
局域网设备（飞牛 / NAS）http://<本机IP>:3456Node 直连，不跳转；需 APP_BIND=0.0.0.0

入口归一在 server.js 顶部：仅 Host 为本机 localhost/127.0.0.1:3456 的页面导航 302 到 80； 局域网 IP 直连放行（跳 localhost 会指向设备自身）。APP_BIND：0.0.0.0（默认，局域网可达）/ 127.0.0.1（仅本机回源）。详见 docs/03-部署与运维 §8。

公网 IPv6 接入（DDNS）

外网 IPv6 → 反代 [::]:80/443 → 127.0.0.1:3456 → app 容器 → db 容器。 容器网络无需开 IPv6：IPv6 由宿主机反代 / 端口映射在入口终结，容器内继续走 IPv4。

  • 确认地址：ip -6 addr show 有 240e:/2408:/2409: global 地址；ip -6 route show default 有默认路由
  • 反代监听：deploy/nginx/jingtu.conf 已含 listen [::]:80/443；校验 ss -6 -lntp | grep -E ':(80|443)\b'，无输出则补 listen [::] 后 reload
  • 反代为容器：端口映射写 "[::]:80:80" / "[::]:443:443"（宿主 IPv6 → DNAT → 容器 IPv4）
  • 飞牛 fnOS 自带反代：面板开 IPv6；面板配置不含 listen [::] 时手工补，之后勿再在面板重存该条
  • DDNS：加 AAAA 记录指向 NAS IPv6，客户端须自动刷新（前缀动态，光猫重启即变）
  • 防火墙：IPv6 入站放行 80/443；3306/3456 不放行公网；APP_URL/CORS_ORIGINS 填域名
  • 验证：curl -6 -g "http://[IPv6]/api/health/ready" → nslookup -type=AAAA 域名 → curl -6 "https://域名/api/health/ready"
  • 80/443 被封：改高位端口（[::]:8443 + APP_URL 带端口）或走隧道；HTTP-01 证书也需 80 可达

生产安全必检（8 条）

  • ① SESSION_SECRET / ENCRYPT_KEY 持久化、权限 600、纳入备份与轮换
  • ② CORS_ORIGINS 限定具体域名（未配置会告警并接受任意来源）
  • ③ HTTPS + TRUST_PROXY + Secure Cookie 联合验证
  • ④ 防火墙只开 80/443（及 SSH）；3456、3306 不暴露公网（局域网内需飞牛/NAS 直连 3456 时可单独放行该端口）
  • ⑤ 屏蔽 /api-docs、/api-docs.json 公网访问
  • ⑥ 备份覆盖 MySQL + uploads/ + 密钥，并做恢复演练
  • ⑦ 服务账号只写 uploads/backups/logs，不递归写整个仓库
  • ⑧ 进程守护单实例（不支持 cluster：CSRF/WS 映射/VRC 状态在内存）

Docker 镜像加速

  • 项目已内置：基础镜像 docker.1ms.run/library/node:22-slim，MySQL …/mysql:8.0
  • 验证可用源（2026-10-12）：docker.1ms.run · hub.rat.dev
  • 阿里云个人加速器已停止同步、网易/中科大老站已关停，勿用
  • registry-mirrors 只对 docker.io 生效，GHCR 等不适用
  • 飞牛用户直接按 docker-compose.fnos.yml 顶部注释操作即可

API 接口总览

DOC 04 · 全局约定 / 权限 / CSRF / 接口族 / 限流 / 已知差异

全局约定

  • 默认基址 http://<host>:3456；响应格式不统一（success/ok/裸对象/数组/文件/重定向并存）
  • 请求体 JSON 全局 20MB；非上传 POST/PUT 5MB
  • 上传分档：头像 5MB / 群图 10MB / 直播缩略图 20MB / 聊天 100MB / 动态与个人相册 200MB / 主相册 500MB；8 个上传路由均过扩展名+魔数双闸
  • Session Cookie connect.sid：7 天滚动、HttpOnly、SameSite=Lax
  • 版本：/api 前缀 + apiVersion 头；/api-docs 仅 ENABLE_SWAGGER=1 且超管会话可见

权限记号

  • 公开 无需登录
  • requireAuth 登录即可（只校验 userId 存在）
  • requireAdminCompat admin + super_admin
  • requireSuperAdmin 仅超级管理员（运维/安全类接口）
  • 专用守卫 聊天/直播 requireChatAuth 等

CSRF

  • GET /api/csrf-token 取 token；除 GET/HEAD/OPTIONS 外默认全校验
  • 精确豁免 15 条路径（登录/init/登出/密码重置/setup 全流程）
  • 前端 window.api() 自动带 token，勿手动处理

数据库设计

DOC 05 · 引擎 / 核心表族 / 索引约束 / 枚举 / 数据保护

引擎与连接

  • 默认 MySQL 5.7+/8.0+（utf8mb4 + utf8mb4_unicode_ci + InnoDB）
  • 可选 SQLite 单机（JINGTU_DB_ENGINE=sqlite，93 张表同上口径，Session 回退 MemoryStore）
  • 连接默认 127.0.0.1:3306 / 库 jingtu_group；时区 +08:00

设计原则

  • 主键 INT AUTO_INCREMENT（config_key、world_id 等为业务主键）
  • 仅 user_group_membership 与 user_like 共 4 个外键，其余应用层维护
  • 部分表软删除（is_active / status / deleted_at 模式不一）；表名单复数混用

索引与约束

  • 20 组高频查询索引（活动时间/用户外键/聊天会话/已读位置等）
  • 约 26 组唯一约束（防重复报名/签到/点赞/组队等）
  • 可选 migrate-optimization.js 建 5 张 *_archive 表 + chat_offline_summary
