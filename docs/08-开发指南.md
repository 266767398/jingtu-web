# 08 · 开发指南

## 1. 运行与调试

```bash
cd server
npm ci                # 安装依赖
node db_init.js       # 建表/迁移（幂等）
npm start             # 开发默认监听 0.0.0.0:3456
```

- `.env` 放仓库根目录（Node `dotenv` 读取）；`server/` 内命令必须在 `server/` 目录执行。
- 测试：`npm test`（Jest）/ `npm run test:node`（node:test）；lint：`npm run lint`。
- Swagger：`ENABLE_SWAGGER=1` 显式开启，仅超管可见（`/api-docs`）。

## 2. 后端约定

- 路由：`server/routes/*.js`，Express Router，统一挂载 `/api/<前缀>`（见 `server.js` 挂载表）。
- 响应：新接口统一 `{success:true, ...}` / 失败 `{success:false, error:'串', code}`；老接口双轨并存，
  兼容层在前端 `errText()`。
- 权限守卫：`requireAuth` / `requireAdminCompat` / `requireSuperAdmin`（`server/auth.js`）。
- 业务码：`ErrorCodes`（`server/utils.js`），带 `GIT_*` 等业务码的错误文案由后端 message 下发、
  前端语言包不翻译（回落显示原文）——新增业务码时同样**不要**加翻译。
- 安全底线：**所有外部命令走 `execFile` 数组直传**（禁止 shell 拼接）；上传必过 `secureUpload`；
  写接口默认受 CSRF 保护。
- 定时任务：`server/schedule.js` 注册（缓存预热/清理/备份/提醒等），保持幂等可重复调度。
- 数据库：一律经 `db.js` 连接池；模式变更写进 `db_init.js`（幂等 ALTER），并同步 `migrate.js` 版本。

## 3. 前端约定

- 无框架单页：`index.html` Tab 结构 + `core.js`（api/apiForm/errText/CSRF/toast）+ `main.js` 调度 +
  `loader.js` 懒加载。**新页面 = 新 JS 模块 + loader 注册**，不引入打包器。
- 语言包：`public/js/languages/*.js`，6 语言；新增文案必须同时补 6 份或至少回退 zh。
- 全局函数命名空间（`window.*`）：同名函数静默覆盖，命名须唯一且带语义。
- 上传：`uploadWithProgress`（core.js）；`window.__imgFail` / `__avatarFail` 统一兜底。
- WebSocket：走 `ws_service`，身份来自 Session；服务端 30s ping / 客户端 25s ping。
- 无障碍：Tab 需 role/tabpanel + 键盘导航；弹窗用 `lockBodyScroll(owner)` 引用计数滚动锁。

## 4. 在线更新功能（超管专属）

- 后端 `server/routes/git_update.js`：`git-status` / `git-update` / `git-restart` 三端点。
- 更新流程：fetch → ahead/behind 保护 → `merge --ff-only` → 变更清单 → `server/package.json` 变更自动
  `npm install`（失败仅告警）→ 操作日志 → 可选自动重启。
- 重启跨平台：Windows WMI 中继 / POSIX 独立会话 helper（约 2~3 秒中断）；日志落 `logs/restart-*.log`。
- 新增该功能的验收必须跑 E2E：`ai-scratch/verify_git_update_restart.py`（Playwright，socket 毫秒级探测）。

## 5. 提交规范

- 遵循 Conventional Commits：`feat/fix/docs/refactor/test/chore(scope): 描述`（本仓库使用中文描述）。
- 每次提交前：`npm run lint` + `node --check` 涉及文件；涉及 db 变更需跑 `db_init.js` 幂等验证。
- 涉及部署/运维/功能变化时，同步更新 `docs/` 对应文档与 `docs/09-变更记录.md`。
- 不提交密钥：`.env`、`docker.env`、`panel-auth.json` 等在 `.gitignore`。

### 6.4 已知差异与政策边界（Tupper Policy）

- 收藏分组：官方 1.21.0 新增 `/favorites/groups/{type}/{name}`，旧式 `/favorite/group/...` 仍可用；
  本地沿用旧式，迁移时以 `ai-scratch/vrcapi-spec` 为准核对。
- 群组相册：官方已迁移为复数 `/groups/{groupId}/galleries`（多相册），本地仍为单数 `/gallery`；
  新功能一律按复数 `galleries` 实现。
- 限流：官方约 50 req/min，本地 `server/vrc.js` 已内置 40/min 令牌桶，新增端点必须复用 `vrchatRequest`。
- 政策红线：只允许符合 VRChat ToS/社区指南的用途；禁止客户端修改、avatar ripping、自动化刷接口；
  moderation 类端点（屏蔽/静音/举报）只允许人工触发，禁止做成批量自动化；接口可能随时破坏性变更。
