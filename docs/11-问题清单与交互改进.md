## 二、高优先级问题（Bug / 服务可用性）

### P1 — 线上站点不可访问

- **现象**：访问 `http://47.105.33.180:3456/` 时 TCP 连接建立成功，但 HTTP 层返回 0 字节，浏览器表现为「无响应 / 连接被重置」。
- **可能原因**：
  1. Node 服务进程假死（事件循环阻塞，端口仍被占用）；
  2. 反向代理（Nginx）对上游静默丢弃，未返回 502；
  3. 服务器资源耗尽（内存/句柄泄漏）。
- **建议排查路径**：
  ```bash
  # 服务器上
  ss -lntp | grep 3456            # 确认端口占用与 PID
  systemctl status <service>      # 确认进程状态
  curl -v http://127.0.0.1:3456/  # 绕开反代直连本机，定位是进程还是反代问题
  journalctl -u <service> -n 200  # 看崩溃/异常日志
  ```
- **关联风险**：该问题不是代码 bug，但属于「反用户」级别最高的一类——站点不可用。

## 三、可访问性问题（a11y）

### A1 — `div` 冒充按钮（头像偏好选择）

- **位置**：`public/index.html` L1769、L1774
- **现状**：
  ```html
  <div class="avatar-pref-item" id="prefCustom" onclick="selectAvatarPref('custom')">
  <div class="avatar-pref-item" id="prefVrc" onclick="selectAvatarPref('vrchat')">
  ```
- **问题**：`div` + `onclick` 无法被键盘聚焦，无法通过 Enter/Space 触发，屏幕阅读器不识别为可交互元素，也没有 `:focus-visible` 样式。
- **修复方向**：改为 `<button type="button" class="avatar-pref-item" ...>`，移除 `onclick`，由 JS 委托或直接绑定事件。

### A2 — 主标签栏缺方向键导航

- **位置**：`public/index.html` L474–L489（`.tabs`）
- **现状**：已声明 `role="tablist"` / `role="tab"` / `aria-selected`，但**未实现 WAI-ARIA Tabs 模式的方向键导航**（`ArrowLeft` / `ArrowRight` / `Home` / `End`）。全局 JS 中搜索 `ArrowLeft|ArrowRight` 仅命中 `posts.js` 的媒体查看器，标签栏无相关处理。
- **影响**：键盘用户（及屏幕阅读器用户）无法在标签之间移动焦点，只能 Tab 逐个经过全部 15 个标签。
- **修复方向**：在 `ui.js` 的标签切换逻辑中补充方向键处理，配合 `roving tabindex`（非激活 tab 设 `tabindex="-1"`）。

### A3 — `role="tab"` 缺 `aria-controls`

- **位置**：`public/index.html` L475–L489
- **现状**：每个 tab 按钮没有 `aria-controls` 指向对应面板，且面板（tab content）未见 `role="tabpanel"` 标注。
- **修复方向**：为每个 tab 补充 `aria-controls="tabpanel-<name>"`，为内容容器补充 `role="tabpanel"` 与 `aria-labelledby`。

### A4 — 部分 `button` 缺 `type`

- **位置**：`public/index.html` 多处（如 L548、L1199、L1200、L1527、L1528 等）
- **现状**：`<button class="...">` 未写 `type="button"`。默认 `type="submit"`，若将来被包进 `<form>` 会触发意外提交。
- **修复方向**：全局补 `type="button"`（纯交互按钮）。

## 四、反用户 / 交互问题

### U1 — 大量内联 `onclick`

- **位置**：`public/index.html` 约 20 处（L539、L540、L548、L618、L620、L622、L661–664、L942–944、L1199、L1200、L1527、L1528、L1769、L1774、L1951 等）
- **问题**：
  1. 内联 handler 依赖全局函数名，任何重命名/模块化都会静默失效；
  2. 无法通过 CSP `script-src` 收紧（内联事件属 unsafe-inline）；
  3. 214KB 的单文件 HTML 越滚越臃肿，维护成本高。
- **修复方向**：逐步迁移到事件委托（参考 `home.js` 里 `document.addEventListener('click', ...)` 的既有模式）。

### U2 — `me-stats` 大量内联 `style`

- **位置**：`public/index.html` L1815–L1827
- **问题**：统计卡片用内联样式写死布局/颜色，无法被主题变量统一管理，深色/浅色主题下可能不一致。
- **修复方向**：抽成 CSS 类，走 `var(--*)` 主题变量。

## 五、UI / CSS 冗余与冲突

### C1 — `.btn` 伪元素三重波纹

- **位置**：
  - `public/css/animations.css`：`.btn::after`（`transform` 波纹）
  - `public/css/ui-enhance.css` §7：`.btn::after`（`radial-gradient` hover 光晕，`inset:0`）
  - `public/css/ui-enhance.css` §46：`.btn::before`（`scale(4)` 点击波纹）
- **问题**：`::after` 被两个文件重复定义，后加载者覆盖前者，实际只有一种生效；`::before` 的点击波纹 `transform: scale(4)` 无 `transition` 收回（从 `scale(0)` 到 `scale(4)` 是单向的，松开后瞬间回到 0，视觉上生硬）。与 `motion.js` 的 `bindRipple()`（注入 `motion-ripple` span）存在功能重叠。
- **修复方向**：统一为单一波纹实现，优先保留 `motion.js` 的 span 波纹（支持 `prefers-reduced-motion`），移除 CSS 伪元素波纹，消除三重覆盖。

### C2 — `.list-item` 双重入场动画

- **位置**：
  - `public/css/ui-enhance.css` §48：`.list-item { opacity:0; animation: fadeInUp ... }`
  - `public/js/motion.js`：`REVEAL_SEL` 包含 `.list-item`，GSAP 会再次操作 `opacity`/`transform`
- **问题**：CSS 关键帧动画与 GSAP 补间同时作用于同一元素的同一属性，可能出现首帧闪烁或跳动。
- **修复方向**：二者取其一。建议让 `.list-item` 的入场动画统一交给 GSAP（`motion.js`）管理，CSS 侧删除 §48 的 `opacity:0` 初始态，避免无 JS 时内容永久隐藏。

### C3 — `.tab` 媒体查询内重复定义

- **位置**：`public/css/03-layout.css` 768px 媒体查询内 `.tab` 定义两次（12px 之后又被 13px 覆盖）
- **问题**：冗余、易误导。后者覆盖前者，前者死代码。
- **修复方向**：删除前者，仅保留生效的那条。

### U3 — `03-layout.css` 单行压缩

- **位置**：`public/css/03-layout.css`
- **问题**：整份文件被压成极少数超长行，无法 diff、无法 review、冲突合并困难。
- **修复方向**：重新格式化（多行、保留逻辑）。

### U4 — 注释残留重复

- **位置**：`public/index.html` L1535–L1536
- **问题**：`<!-- 操作日志 -->` 后紧跟一个已关闭的 section，再重复出现一次 `<!-- 操作日志 -->`。
- **修复方向**：清理残留注释。

## 六、现有动画系统盘点（避免重复造轮子）

| 层 | 文件 | 职责 |
|---|---|---|
| 动效主层 | `public/js/motion.js` | GSAP 滚动揭示、ripple 微交互、视图切换过渡、MutationObserver |
| 揭示降级 | `public/js/reveal.js` | IntersectionObserver 滚动揭示（GSAP 接管时让位） |
| CSS 动画库 | `public/css/animations.css` | fadeIn/slideIn/zoomIn/bounceIn/shake 等 20+ 关键帧 |
| UI 增强 | `public/css/ui-enhance.css` | 卡片微交互、骨架屏、toast、骨架、涟漪等 |
| 点赞动效 | `public/css/likes-anim.css` | 心形爆裂（`like-burst`） |
| 空闲冻结 | `public/js/freeze.js` | 2 分钟无操作冻结轮询/WS 心跳 |

现有体系已覆盖：滚动揭示、卡片 hover 上浮、toast 滑入、弹窗缩放、tab 滑动指示器、点赞爆裂、消息气泡、骨架屏、进度条、按钮波纹。

**结论**：动画「量」已足够，缺的是**一致性**（C1/C2 的重复冲突）与**针对性反馈**（见 §7）。

## 七、建议新增的交互动画（尊重 `prefers-reduced-motion`）

> 全部新增动画必须走 `motion.js` 的 `reduce` 检测或 CSS `@media (prefers-reduced-motion: reduce)` 降级，与 `likes-anim.css` 的 `force-anim` 逃生舱保持一致。

1. **未读数气泡弹性弹出**（已有 `badgePop`，建议补 `transition` 而非一次性 animation，避免重复触发不重放）。
2. **在线状态点呼吸**（`online-dot.on` / `status-dot.online` 已有 `pulse-glow`，可增强为「柔和呼吸 + 光晕扩散」双层）。
3. **数字滚动**：首页 `hs-value` 与仪表盘 `dashboard-value` 从旧值滚动到新值（`requestAnimationFrame` 补间）。
4. **卡片 3D 倾斜**（桌面端）：`.member-card` 随鼠标位置轻微 `rotateX/rotateY`（需 `mousemove` 节流 + `reduced-motion` 禁用）。
5. **下拉菜单柔化**：现有 `.dropdown-menu` 为 `translateY(-8px) scale(.95)`，可加入 `filter: blur` 过渡，观感更顺。
6. **空状态插画微动**：`renderEmpty` 生成的空状态图标可加轻微浮动（`float` 关键帧）。
