## 二、i18n 语言包问题

### 2.1 六个 `-ext.js` 补键包从未被加载 🔴

`public/js/languages/` 下存在 6 个补键包：`zh-ext.js` / `en-ext.js` / `ja-ext.js` / `fr-ext.js` / `de-ext.js` / `ru-ext.js`（V7.11 时期产出，文件头注释写明「合并进 window._LANG_XX」）。

**事实**：全站检索（`index.html`、`public/js/**/*.js`）没有任何一处加载这些文件——既不在 `index.html:81` 的 `document.write` 语言包引入里，也不在 `i18n.js` 的 `ensurePacks` / `setLanguage` 按需注入逻辑里（两处都只拼 `'/js/languages/' + lang + '.js'`）。

**影响面**（以 zh-ext 为例，独有键 57 个，主包已有键不重复计入）：

| 前缀 | 键数 | 运行时是否被用到 |
|------|------|------------------|
| `social.*` | 25 | 否（活跃代码无静态引用） |
| `checkin.*` | 17 | 否 |
| `collections.*` | 8 | 否 |
| `admin.*`（restore 系列） | 5 | 否 |
| `nav.friends` / `nav.follows` | 2 | **是**（`home.js` 动态拼接，见 2.2） |

结论：ext 包中目前唯一被运行时触达的是 `nav.friends` / `nav.follows`；其余键属于「功能未接线或已改用其他键」的孤儿键。修复时二选一：① 在 `index.html`/`i18n.js` 加载 ext 包；② 把仍需要的键（至少 nav 两个）并入主包并删除 ext 死文件。**注意**：`zh-ext.js` 的 `nav.more: "更多"` 与主包 `nav.more: "全部功能"` 冲突，ext 的合并策略是「已有键不覆盖」，加载顺序会决定最终文案，修复时需明确取舍。

### 2.2 `nav.friends` / `nav.follows` 运行时缺失 🔴

- `home.js:47-48`：首页功能网格含 `{ tab: 'friends' }`、`{ tab: 'follows' }` 两项；
- `home.js:74`：`const title = __('nav.' + it.tab);` 动态取键；
- `zh.js` 主包 nav 系列有 24 个键（home/members/group/…/modelcoll），**无** `nav.friends`、`nav.follows`；
- 这两个键只存在于未加载的 `zh-ext.js`。

**用户可见**：中文环境下首页「好友」「关注」两张功能卡显示原始键名 `nav.friends` / `nav.follows`；其他语言同理（且其他语言连 ext 里也没有这两个键）。

### 2.3 语言包缓存版本号不一致且过期 🔴

同一批语言包文件存在**两个不同的缓存版本号**：

| 加载路径 | 版本号 | 位置 |
|----------|--------|------|
| 首屏 `document.write` 加载当前语言包 | `20260818t` | `index.html:81` |
| 切换语言 / 兜底按需注入 | `20260822a`（`I18N_PACK_VERSION`） | `i18n.js:38` |

而语言包内容在 08-22 之后仍在持续新增（如 08-31 V9.4 一次性新增 12 个 `map.*` 键）。后果：
1. 08-18/08-22 之前访问过的用户，浏览器/SW 缓存命中旧版本语言包，新键全部显示原始 key；
2. 同一文件以两个 URL 缓存，浪费且行为不一致。
3. `i18n.js:35-37` 注释本身已声明「语言包内容更新时需同步提升此版本号」——近期多轮更新均未执行该约定。
