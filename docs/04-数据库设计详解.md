# 境途同游 Web 项目 — 数据库设计详解

> 版本：V7.10  
> 最后更新：2026-08-09

## 一、数据库概述

### 1.1 基本信息

| 属性 | 值 |
|------|-----|
| 数据库类型 | MySQL 5.7（当前一键启动脚本固定为 5.7.26；SQL 兼容 MySQL 5.7） |
| 字符集 | utf8mb4 |
| 排序规则 | utf8mb4_unicode_ci |
| 存储引擎 | InnoDB |
| 标准表数量 | 55 张（`db_init.js` 的 `CREATE TABLE` 清单） |
| 运行时表 | `sessions`（由 `express-mysql-session` 创建，不属于上述 55 张） |
| 可选优化表 | 5 张 `*_archive` 归档表和 `chat_offline_summary`（仅手动执行 `migrate-optimization.js` 时创建） |
| 主键类型 | 以 `INT AUTO_INCREMENT` 为主，存在业务键及无独立主键的例外 |

### 1.2 数据库连接配置

```dotenv
MYSQL_HOST=127.0.0.1
MYSQL_PORT=3306
MYSQL_USER=root
MYSQL_PASSWORD=
MYSQL_DATABASE=jingtu_group
```

`server/server.js` 从项目根目录 `.env` 加载配置。以上名称和默认值来自
`server/db.js` 与 `server/server.js`；代码不读取 `DB_HOST`、`DB_PORT`、
`DB_USER`、`DB_PASS` 或 `DB_NAME`。业务连接会 trim `MYSQL_PASSWORD` 并去掉
成对的单双引号，空密码不会写入 `DB_CONFIG`；Session Store 则直接使用
`MYSQL_PASSWORD || ''`。端口通过 `parseInt` 解析，解析失败或为 `0` 时回退到
`3306`。

当前启动入口：

- `server/package.json` 的 `npm start` 执行 `node server.js`。
- 根目录 `start-services.ps1` 使用硬编码目录启动 MySQL **5.7.26**、Nginx 和
  `node server.js`；`start-services.bat` 仅切换到其硬编码项目目录后调用该
  PowerShell 脚本。
- `server.js` 每次启动都会 `await require('./db_init')()`：先以无数据库连接
  尝试创建 `MYSQL_DATABASE`（最多 3 次，间隔 2 秒、4 秒），再重建连接池，
  执行 55 个 `CREATE TABLE IF NOT EXISTS`、兼容旧库的 `ALTER TABLE` 和默认
  数据写入。初始化失败会记录警告，但 HTTP 服务仍会监听端口，供 setup 引导。
- `db_init.js` 特意用捕获重复列/索引错误的方式兼容 MySQL 5.7；不能据此要求
  MySQL 8.0。JSON 字段要求实际 5.7 版本具备 JSON 支持，当前 5.7.26 满足。

### 1.3 设计原则

| 原则 | 说明 |
|------|------|
| **主键设计** | 多数表使用 `id INT AUTO_INCREMENT`；`system_config.config_key`、`vrc_worlds_cache.world_id` 是业务主键，`user_profile` 仅以 `user_id NOT NULL UNIQUE` 标识一对一记录 |
| **软删除** | 仅部分表具备软删除/归档字段，例如 `users.deleted_at`、消息表的 `deleted_at`、`event.is_archive` |
| **时间戳** | 字段按业务混用 `create_time`/`created_at`、`update_time`/`updated_at`，并非所有表都有成对时间戳 |
| **外键约束** | 标准初始化仅在 `user_group_membership` 与 `user_like` 声明 4 个数据库外键，其余 ID/VRChat ID 关系主要由应用层维护 |
| **索引优化** | 高频查询字段建立索引 |
| **字符集** | 建库使用 `utf8mb4_unicode_ci`；各表使用 `utf8mb4`，部分表显式指定该排序规则 |
| **字段命名** | 字段整体采用 `snake_case`，但时间字段保留现有历史命名，不能假定完全统一 |
| **表名命名** | 历史上混用单数（`event`、`announcement`）和复数（`users`、`posts`、`messages`）；以实际表名为准 |

### 1.4 迁移版本控制

`db_init.js` 使用 `INSERT IGNORE` 在 `system_config` 中写入以下标记；这是初始化
状态记录，不表示启动时会自动执行所有独立迁移脚本：

| config_key | 说明 |
|------------|------|
| db_migration_version | 当前数据库版本号（如 7.00） |
| db_last_migration | 最后迁移时间（NOW()） |

标准业务表名称为（新增表随版本迭代，完整变更见 §22 版本变更记录）：

`password_reset_tokens`、`sys_admin`、`sys_oper_log`、`announcement`、
`announcement_attachments`、`announcement_history`、`event`、`event_sign`、
`album_cate`、`album_photo`、`album_like`、`album_comment`、`user_profile`、
`users`、`group_roster`、`group_member_changes`、`group_sync_log`、
`group_invites`、`user_albums`、`user_photos`、`user_videos`、`member_note`、
`name_change_requests`、`permissions`、`event_checkin`、`event_comment`、
`vrc_worlds_cache`、`notifications`、`messages`、`chat_groups`、
`chat_group_members`、`chat_group_messages`、`chat_group_message_reads`、
`live_streams`、`live_viewers`、`live_comments`、`live_likes`、
`permission_groups`、`group_permission_entries`、`user_group_membership`、
`system_config`、`posts`、`post_media`、`post_like`、`post_comment`、`webhooks`、
`user_like`、`world_favorites`、`avatar_favorites`、`user_checkin`、
`checkin_rewards`、`achievements`、`user_achievements`、`event_teams`、
`event_team_members`、`avatar_tags`（F-16）、`world_tags`（F-17）。

下文表结构描述的是一次完整 `initDatabase()` 执行后的**有效结构**：既包括
`CREATE TABLE` 本体，也包括同一函数随后执行的兼容性 `ALTER TABLE`。源码末尾
“29张表”的控制台文案是未同步更新的旧日志，不能作为表数依据。

`sessions` 不在 `db_init.js` 中。`server.js` 配置
`express-mysql-session`（当前依赖 `^3.0.3`）时设置
`createDatabaseTable: true`、`schema.tableName: 'sessions'` 和 7 天过期时间，
由该依赖按需建表；依赖加载失败才回退到进程内 MemoryStore。因此它是会话存储
基础设施表，不应计入标准业务表或拿 `db_init.js` 的字段规范推断其结构。

`migrate-optimization.js` 也不在 `npm start`、`npm run migrate` 或根目录启动
脚本中。只有手动执行它才会创建
`messages_archive`、`chat_group_messages_archive`、`posts_archive`、
`event_archive`、`group_sync_log_archive`（均由 `LIKE` 复制标准表后添加
`archived_at`）以及 `chat_offline_summary`。这些可选表不计入 55 张标准表。

## 二、ER 关系图

### 2.1 核心业务关系

以下为字段表达的**逻辑关系**；除明确标注数据库外键者外，均由应用层维护：

```text
users ── user_profile / posts / post_media / post_like / post_comment
      ├─ messages（sender_id、receiver_id）
      ├─ chat_groups（creator_id）/ chat_group_members / chat_group_messages
      ├─ notifications / live_streams / live_viewers / live_comments / live_likes
      ├─ user_albums / user_photos / user_videos
      ├─ user_checkin / user_achievements / world_favorites / avatar_favorites
      ├─ event_checkin / event_comment / event_teams / event_team_members
      └─ user_like（from_user_id、to_user_id；数据库外键）

event ── event_sign / event_checkin / event_comment / event_teams
      └─ album_photo（event_id）
event_teams ── event_team_members

posts ── post_media / post_like / post_comment
chat_groups ── chat_group_members / chat_group_messages / chat_group_message_reads
chat_group_messages ── chat_group_message_reads
live_streams ── live_viewers / live_comments / live_likes
album_cate ── album_photo
album_photo ── album_like / album_comment
user_albums ── user_photos
```

特别注意：`event_sign.user_vrcid` 逻辑对应 `users.vrchat_id`，不是
`users.id`；`member_note.owner_id`/`target_id` 逻辑对应 `users.id`。
`messages` 与 `chat_groups` 之间没有直接关系，`posts` 与 `event` 之间也没有
直接关系。

### 2.2 权限与群组关系

```text
users ──< user_group_membership >── permission_groups
permission_groups ──< group_permission_entries
```

其中 `user_group_membership.user_id/group_id` 是数据库外键；
`group_permission_entries.group_id` 和 `permission_groups.parent_id` 在标准初始化
中仅为应用层引用。

### 2.3 签到与成就关系

```text
users ──< user_checkin
users ──< user_achievements >── achievements
users ──< world_favorites
users ──< avatar_favorites
```

这些均是标准表中的应用层引用，不是数据库外键。

## 二十、关系与数据库外键边界

本项目大部分关联通过应用层维护。标准 `CREATE TABLE` 中实际定义的数据库外键
仅有：
- `user_group_membership`: `FOREIGN KEY (user_id) REFERENCES users(id) ON DELETE CASCADE`, `FOREIGN KEY (group_id) REFERENCES permission_groups(id) ON DELETE CASCADE`
- `user_like`: `FOREIGN KEY (from_user_id) REFERENCES users(id) ON DELETE CASCADE`, `FOREIGN KEY (to_user_id) REFERENCES users(id) ON DELETE CASCADE`

其余关系应称为逻辑引用，不应标成数据库外键。容易混淆的正确对应是：

- `event_sign.user_vrcid` → `users.vrchat_id`（VARCHAR），不是 `users.id`。
- `member_note.owner_id`、`member_note.target_id` → `users.id`。
- `album_photo.event_id` → `event.id`，不是 `album_cate.id`。
- `user_photos.album_id` → `user_albums.id`，不是 `album_cate.id`。
- `chat_group_message_reads.group_id` → `chat_groups.id`，
  `message_id` → `chat_group_messages.id`。

可选的 `migrate-optimization.js` 会尝试为更多现有表添加外键；只有实际手动执行
成功后它们才存在，不能当作标准初始化保证。
