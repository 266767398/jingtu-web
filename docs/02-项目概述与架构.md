# 02 · 项目概述与架构

## 1. 定位

面向 **VRChat 社群**的一体化单体 Web 应用：原生 HTML/CSS/JS 前端 + Node.js/Express 后端，
同时提供静态文件、HTTP API 与 WebSocket；业务数据与 Session 存 MySQL（可选 SQLite 单机模式）。

## 2. 技术栈

| 层 | 技术 |
|---|---|
| 后端 | Node.js ≥20、Express 4、mysql2（可 `JINGTU_DB_ENGINE=sqlite` 切 node:sqlite）、express-session + express-mysql-session、bcryptjs、ws、Multer/Sharp、node-schedule/cron、Nodemailer |
| 前端 | 原生 JS/CSS（无框架、无打包器）；i18n 6 语言；Leaflet 地图（CDN）；PWA（Manifest + sw.js） |
| 可选 | Redis（缓存/限流/CSRF 共享态）、PM2（单实例）、Nginx/TLS 反代、Docker Compose |

## 4. 启动与请求架构

- 启动顺序：读 `.env` → 建 app（3456）→ 入口归一 → 中间件 → VRChat Pipeline → 业务路由 → /ws → db_init（失败仅告警）→ listen（绑定地址取 `APP_BIND`，默认 `0.0.0.0`）。
- 中间件主链：入口归一 → CORS → compression → 安全头 → /api 限流(600/分/IP) → 可疑检测 → metrics → JSON(20MB)
  → WAF → UTF-8 包装 → 静态 → Session → 账户校验 → 分级限流 → CSRF → 业务路由。
- 入口约定（本机 / 局域网双形态）：
  - 本机浏览器规范入口为 `http://localhost`（Nginx 80 反代到 Node 3456）；直连 `localhost:3456` / `127.0.0.1:3456` 的页面导航会 302 到 80 同路径，消除「80 / 3456 两个本机入口」的困惑。
  - 局域网设备（如飞牛 / NAS）直接访问 `http://<本机IP>:3456`，**不做跳转**（跳 `localhost` 会指向设备自身）。
  - `APP_BIND` 控制 Node 监听地址：`0.0.0.0`（默认，局域网可达）/ `127.0.0.1`（仅本机回源）。API / 静态资源 / WebSocket 不受入口归一影响。
- Session：MySQL 存储（失败回退 MemoryStore），Cookie `connect.sid` 7 天滚动、HttpOnly、SameSite=Lax；
  角色三档 `super_admin / admin / member`；bcrypt cost 12。
- 前端：`index.html` Tab 式单页（非 URL 路由），`loader.js` 按需懒加载 33 个业务模块（M2 拆分 chat.js → rtc/location-share/group-manage；后续新增 admin-files/admin-security/admin-webhooks），`main.js`
  交错刷新（30 秒首刷 / 75 秒轮换）。

## 5. 实时通信

- `/ws` 与 HTTP 共用 Server：解析 `connect.sid` 验签后固定身份；服务端 30 秒 ping、10 分钟超时、
  断线指数退避重连（最多 10 次）。
- VRChat 数据源：`vrc_pipeline` 连 `wss://pipeline.vrchat.cloud`，支持 6 类事件；凭据 AES-256-GCM
  加密存 `server/data/session.json`（Docker 挂载卷可写；旧版 `server/session.json` 自动迁移读取）；F-29 会话被拒暂停重连 + 自动重登（TOTP 可自动）；F-30 双护栏
  （60s 最小间隔 + 5min×3^n 封顶 30min 指数退避）。

## 6. 定时任务（schedule.js + tasks.js，随服务启动）

**schedule.js（node-schedule，13 项）**：缓存预热（每日 1:00）、回收站清理（每日 2:00）、活动归档（每日 3:00）、
邀请过期（每日 4:00）、Token/活动提醒、每 60 秒 VRChat 在线状态刷新（30s→60s 已放宽，游标轮转 + 名册兜底同步 +
信任等级补充）、每 5 分钟在线名册缓存、每分钟好友/世界/会话/头像历史 diff、每日 5:00 模型收藏失效检测。

**tasks.js（node-cron，8 项）**：每小时过期会话清理、每日 2:00 文件/通知清理、每日 02:30 数据备份（`auto_` 前缀，
保留天数可配）、每日 3:00 备份与分享链接清理、**每 10 分钟地图死坐标清扫（cleanupStaleLocations）**、每日 0:00 每日统计。
