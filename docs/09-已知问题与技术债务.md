**关于「网站能否正常显示 VRChat 群组信息」的核查结论（用户曾要求百度查 VRChat 公开 API）：**
- VRChat 官方 API **没有真正的匿名/公开接口**：群组、成员、帖子、世界、头像等接口均要求 `auth=` 登录 cookie 鉴权（项目里通过 `getVRCCookieFn` 取「用户绑定 cookie → 系统账号 cookie」并 `vrcWithFallback` 自动降级）。`apiKey` 查询参数只是应用标识，不能替代用户登录态。换言之：**没有任何公开 API 能匿名拉取群组信息**。
- 网站群组数据有**两条来源**：
  1. **缓存快照**（成员列表 / 在线状态 / 所在世界 / 群是否存在）：读本地 `group_roster` 表，**不调 VRChat 实时接口**。只要 **MySQL 在线**就能显示——显示的是「最近一次同步后的快照」，VRChat 挂了也不影响。这正是本轮缺库恢复要解决的前提：库挂了连缓存展示也废，恢复后自然恢复。
  2. **实时详情**（群简介、实时在线、世界/头像搜索）：`/api/group`、`/vrc/world*`、`/vrc/avatar*` 等**实时调 VRChat**，必须有有效登录 cookie，否则返回 `401 请先绑定VRChat账号`。cookie 过期 → 实时接口全挂，但「缓存快照」展示仍在（只是变旧）。
- 站点应有周期性「同步群组到 `group_roster`」的任务（用有效 cookie 拉取写入），靠它维持缓存新鲜度；cookie 失效则同步停摆，仅剩陈旧快照。
- **VRCX 公开库印证（vrcx-team/VRCX，MIT 开源）**：VRCX 同为「非官方 VRChat API SDK」，机制与本站点一致——用户在其内嵌浏览器登录 VRChat 后，捕获并持久化 `auth=` cookie 到本地 SQLite，之后所有 `api.vrchat.cloud/api/1/...` 调用都带该 cookie；`apiKey` 仅作 User-Agent 式标识。VRCX 的群组能力（成员/动态/活动）亦来自 `GET /groups/{id}`、`/groups/{id}/members` 等 cookie 鉴权接口，**无匿名公开接口**。官方亦提供自动生成的 `vrchatapi` SDK（Python/JS/Java/Elixir 等，基于 OpenAPI，同样 cookie 鉴权），可作为后续对接参考。

### 3. 静态资源 ETag 协商缓存（server.js）
- **改动前**：`express.static(..., { maxAge: 0, etag: false })` —— 每次访问全量重下 JS/CSS，且全局 `app.set('etag', false)` 关闭了协商缓存。
