# 05 · 数据库设计

> 完整建表 SQL 见 `server/db_init.js`（幂等，可重复执行）。更细的 ER 关系与版本变更见审计/报告清单（旧版详解已并入本文档体系，`docs/archive/` 已清理）。

## 1. 引擎与连接

- 默认 **MySQL 5.7+/8.0+**（`utf8mb4` + `utf8mb4_unicode_ci` + InnoDB）；可选 **SQLite** 单机模式
  （`JINGTU_DB_ENGINE=sqlite`，Session 回退 MemoryStore）。
- 当前库共 **93 张表**（核心建表 87 张 + 归档/收藏/队伍/VRC 缓存等运行时迁移表）。
- 连接默认 `127.0.0.1:3306` / 库 `jingtu_group`；连接时区 `+08:00`（与定时任务 Asia/Shanghai 对齐）。
- `db_init.js`：三次建库重试（2s/4s）→ CREATE DATABASE → 重建连接池 → 关闭 FK 检查 → 建表/ALTER/种子。

## 2. 设计原则

- 主键 INT AUTO_INCREMENT（`config_key`、`world_id` 等为业务主键）。
- 仅 `user_group_membership` 与 `user_like` 共 4 个数据库外键，其余由应用层维护。
- 部分表软删除（`is_active` / `status` / `deleted_at` 等字段模式不一）；表名单复数混用。

## 3. 核心表族

| 族 | 表 | 说明 |
|---|---|---|
| 系统 | `system_config`、`sessions` | 配置键值；express-mysql-session 运行时表 |
| 用户 | `users`（40+ 字段，含签到/成就统计列）、`user_profile`、`member_note`、`user_like`、`name_change_requests` | 用户是业务中心；`users.role` **仅 member/admin/super_admin 三值**（写入时非法值归一为 member）；`users.halo_visible`（光环可见性）、`users.trust_level / trust_checked_at`（**V6.17** 自身信任等级缓存，名册无记录时回填） |
| 群组 | `group_roster`、`group_member_changes`、`group_sync_log`、`group_invites` | 群成员信任等级 `trust_level / trust_level_cn`、变更审计、同步日志 |
| 活动 | `event`（11 索引）、`event_sign`、`event_checkin`、`event_comment`、`event_teams`、`event_team_members` | 报名/签到/组队；`event_sign.user_vrcid` 对应 `users.vrchat_id` |
| 相册/媒体 | `albums`、`album_photos`、`posts` + 媒体、视频、评论 | 相册 500MB 上传、动态媒体 |
| 通知/聊天/直播 | `notifications`、`messages`、`chat_rooms`、`live_rooms`、`vrc_notif_sync` | 站内通知；私聊/群聊；直播元数据；VRChat 通知并入去重 |
| 签到/成就 | `user_checkin`（每日唯一键）、`checkin_rewards`（7 档 10-1000 分）、`achievements`（29 个默认成就）、`user_achievements` | 签到/成就 |
| 收藏/模型 | `collections`、`collection_folders`、`collection_ratings`、`model_ratings`、`model_tag_dict`、`world_favorites`、`avatar_favorites`、`vrc_worlds_cache`、`vrc_fav_cache` | 统一收藏馆（**模型/世界双分类**）+ 旧收藏 + VRC 官方收藏回源缓存 |
| 审核 | `moderations`（remote_result 回显） | 举报/审核队列 |
| 权限组 | `permission_groups`（默认 3 组：**成员根组 → 管理员 → 超管**）、`group_permission_entries`（30 个 `can_*` 键）、`user_group_membership` | 三表模型；**父链继承运行时生效**，系统组层级由 DB 自愈（启动 + 每次权限计算对齐） |
| 标签 | `world_tags`、`avatar-tags` 相关 | V9.4 新增 |

### 3.1 VRChat 缓存 / 同步表

| 表 | 职责 | TTL / 约束 |
|---|---|---|
| `vrc_fav_cache` | 官方收藏条目回源富化结果（名字/封面/作者），跨用户、跨重启共享；内存 → DB → VRChat 三级缓存 | 7 天（查询带 `fetched_at` 窗口），过期行按小时级节流清理；`target_id` 主键 + `type` / `fetched_at` 索引 |
| `vrc_worlds_cache` | 世界详情完整缓存（13 列：名称/描述/图/作者/类型/资源/平台/容量/标签/发布状态），收藏富化与成员在线世界同源 | 24 小时；`world_id` 主键；建表 DDL 已与 world_cache.js 写入列对齐 |
| `vrc_notif_sync` | VRChat 官方通知并入站内通知的去重登记 | `(user_id, vrc_notif_id)` 复合主键 |
| `vrc_account_status` | 系统账号有效性检查结果（valid/invalid/offline/unknown） | `vrchat_id` 唯一；`status` / `last_check` 索引 |
| `vrc_blacklist` | 超管维护的 VRChat 黑名单（用户名/URL/原因） | `vrchat_id` 唯一 |

负缓存说明：`vrc_fav_cache` 回源失败的条目另有 **60s 进程内冷却**（不入库），冷却期内同一目标不再打上游，配合前端「等冷却后重拉」节奏，避免限流期间反而加剧回源。

## 4. 索引与约束

- 20 组高频查询索引（活动时间/用户外键/聊天会话/已读位置等）+ 约 26 组唯一约束
  （防重复报名/签到/点赞/组队等）。
- 可选 `migrate-optimization.js` 手动执行才会建 5 张 `*_archive` 表 + `chat_offline_summary`。

## 5. 关键枚举

`role`(member/admin/super_admin，**仅此三值合法，其余写入归一为 member**)、`avatar_type`、`event_type`、`visibility`、`source`、
`instance_type`、posts `type/visibility`、`privacy`、live `status`、`msg_type`、
`notification.target_type`、achievements `type/condition_type/rarity`、邀请/改名状态等
——定义以 `server/db_init.js` 为准。

## 6. 数据保护（与部署相关）

`.env`、`uploads/`、`assets/`、`server/data/*.sqlite`、`backups/`、`logs/` 均不纳入版本控制；
在线更新 `merge --ff-only` 只动跟踪文件、永不 `git clean`，用户数据不受影响。
