## 2. jtt.js 骨架详情

### 2.1 四个联动方向

| 方向 | 端点组 | 鉴权方式 |
|---|---|---|
| ① 账号文件签发（管理端） | `accounts/issue` / `accounts/export/:id` 等 | Session + CSRF（`requireRole('super_admin')`） |
| ② 游戏状态上报（客户端） | `states/*` | `X-JTT-*` 头 + ED25519 签名（`jttAuth`，免 Session） |
| ③ `jt1://` 深链生成（Web 登录用户） | `deeplink/generate` | `requireAuth` |
| ④ 客户端账号注册联动（仅超管可创建账号） | `bind-codes` + `accounts/register` | 管理端点 super_admin + Session + CSRF；注册端点签名认证（TOFU，首次信任由绑定码带外保证）；客户端侧仅超管可创建账号文件，普通用户不可自助创建 |

### 2.2 常量与工具

| 名称 | 值 / 行为 | 契约依据 |
|---|---|---|
| `SIGNATURE_WINDOW_SEC = 300` | 签名时间戳允许 ±300s 偏移 | §4.1 |
| `GAME_KEY_PATTERN` | `/^[a-z0-9][a-z0-9-_]{1,63}$/`，小写字母数字开头、2–64 位 | §4.2 |
| `JTT_ROLE_WHITELIST` | `['member','admin','super_admin']` | §3.1 |
| `DEEPLINK_TYPES` | `['join','session/start','account/import']` | §5.2 |
| `STATE_RATE_LIMIT_MS = 15 * 1000` | 状态上报限流 ≤1 次/15s/accountId | §6.2 |
| `JTT_ACCOUNT_PREFIX = 'jt_'` | 账号 ID 前缀（`jt_` + 32 位 hex） | §2.1 |
| `buildSignatureString()` | `METHOD \n PATH \n TIMESTAMP \n NONCE \n RAW_BODY` 五段 `\n` 连接 | §4.1 |
| `verifyEd25519()` | Node 内置 `crypto.verify('ed25519', ...)`，零第三方依赖；异常返回 `false` | §4.1 |
| `jttAuth` 中间件 | 读取 4 个 `X-JTT-*` 头 → 时间戳窗口校验 → 验签；**骨架阶段查库与验签留 TODO，统一返回 401 `JTT_ACCOUNT_NOT_FOUND`** | §4.1 |
| `stateReportCache` | 内存 `Map`（accountId → lastReportTs），重启失效 | §6.2 |

### 2.3 端点清单（14 个）

| 端点 | 方法 | 权限 | 契约节 | 骨架当前行为 | 联调 TODO 要点 |
|---|---|---|---|---|---|
| `/accounts/issue` | POST | super_admin | §3.1 | 校验 userId/role 白名单，返回占位 `accountId` | 查目标用户有效性 → 查重（`JTT_ACCOUNT_EXISTS`/`force`）→ 生成 accountId/fingerprint → 密钥对与私钥处理 → 构造完整 `jttAccountFile` |
| `/accounts` | GET | super_admin | §3.2 | 分页参数解析，返回空列表 | 按 userId/revoked 过滤分页查询，剔除敏感字段 |
| `/accounts/export/:id` | GET | super_admin | §3.5 | 校验 id，返回占位 | 组装 `jttAccountFile` 以 JSON 附件返回；已撤销/过期 → 409 |
| `/accounts/:id` | GET | super_admin | §3.3 | 返回 `account:null` | 返回完整记录（含 publicKey/permissions/allowedRooms）；无记录 → 404 |
| `/accounts/:id` | DELETE | super_admin | §3.4 | 返回 `revoked:true` | 逻辑撤销 `revoked=1`，幂等 |
| `/accounts/verify` | POST | jttAuth | §3.6 | `{valid:false, reason:'not_implemented'}` | 比对 fingerprint/clientPublicKey → `valid:true` 或 4 种 `reason` |
| `/accounts/register` | POST | 签名端点（TOFU） | §3.7 | 校验 accountId 格式/必填头，返回占位 | 绑定码校验（INVALID/USED/EXPIRED）→ 时间戳窗口 + nonce → 用请求体 publicKey 验签 → 幂等 → 落库 + 标记绑定码已用 |
| `/bind-codes` | POST | super_admin | §3.8 | 校验 userId/role/expiresInDays，返回占位 `bindCode` | 生成 `JTBC-` 绑定码、落库哈希（原始码仅返回一次）、默认 7 天有效期 |
| `/states` | POST | jttAuth | §4.2 | 校验 gameKey + 内存限流（429），返回占位 state | UPSERT `jtt_game_states`，返回完整 state |
| `/states` | DELETE | jttAuth | §4.3 | `{cleared:true}` | 删除记录，无记录也成功（幂等） |
| `/states/me` | GET | jttAuth | §4.4 | `{state:null}` | 查自己的状态，无记录 → `{state:null}` |
| `/states/online` | GET | requireAuth | §4.6 | 分页参数解析，返回空列表 | 15 分钟 TTL + `visibility != 'private'` 过滤 + JOIN users 取 displayName |
| `/states/:userId` | GET | requireAuth | §4.5 | 校验 userId，返回 `{state:null}` | private 可见性控制（403 `FORBIDDEN`）；无记录 → `{state:null}` |
| `/deeplink/generate` | POST | requireAuth | §5.2 | 校验 type 白名单，返回占位 deepLink | 构造 `jt1://` 链接（参数 URL 编码）+ 票据表（10 分钟一次性） |

### 2.4 路由注册顺序（重要）

- `GET /accounts/export/:id` 注册在 `GET /accounts/:id` **之前**，避免字面路由被参数路由截胡。
- `GET /states/online`、`GET /states/me` 注册在 `GET /states/:userId` **之前**。
- 方向④ 的 `/accounts/register`、`/bind-codes` 均为 POST 字面路由，与现有 `GET/DELETE /accounts/:id` 参数路由方法不同、不冲突；已放在方向③ 区块之后、`module.exports` 之前。
- 启动期 `route_guard.js` 会自检重复路由与截胡，保持上述顺序可避免告警。

## 3. 数据表（db_init.js 追加，MySQL 5.7 / utf8mb4 / InnoDB）

### 3.1 `jtt_accounts` — 账号文件签发记录表

| 字段 | 类型 | 约束 | 说明 |
|---|---|---|---|
| id | INT | PRIMARY KEY AUTO_INCREMENT | 主键 |
| user_id | INT | NOT NULL | 站内用户（users.id，逻辑引用） |
| account_id | VARCHAR(64) | NOT NULL UNIQUE | 境途账号 ID（`jt_` + 32 位 hex） |
| display_name | VARCHAR(100) | NOT NULL | 签发时快照的显示名 |
| role | VARCHAR(20) | DEFAULT 'member' | 境途侧角色 |
| public_key | TEXT | NOT NULL | 客户端生成的 ED25519 公钥（Base64） |
| permissions | JSON | NULL | 境途权限列表 |
| allowed_rooms | JSON | NULL | 房间/会话白名单 |
| fingerprint | VARCHAR(64) | NOT NULL UNIQUE | 账号文件指纹（公钥哈希） |
| issued_by | INT | NULL | 签发人（users.id；方向④ 注册时为绑定码生成人） |
| issued_at | DATETIME | DEFAULT CURRENT_TIMESTAMP | 签发时间 |
| expires_at | DATETIME | NULL | 过期时间（NULL=长期有效） |
| revoked | TINYINT(1) | DEFAULT 0 | 是否已撤销 |
| revoked_at | DATETIME | NULL | 撤销时间 |
| created_at / updated_at | DATETIME | DEFAULT CURRENT_TIMESTAMP / ON UPDATE | 时间戳 |

索引：`uk_account_id`、`uk_fingerprint`、`idx_user`、`idx_revoked`、`idx_expires`

### 3.2 `jtt_game_states` — 游戏状态表（每用户一条当前状态）

| 字段 | 类型 | 约束 | 说明 |
|---|---|---|---|
| id | INT | PRIMARY KEY AUTO_INCREMENT | 主键 |
| user_id | INT | NOT NULL UNIQUE | 站内用户（UPSERT 键） |
| game_key | VARCHAR(64) | NOT NULL | 游戏标识（如 lol / cs2 / dota2） |
| game_name | VARCHAR(100) | NOT NULL | 展示名（如 英雄联盟） |
| started_at | DATETIME | NULL | 游戏开始时间 |
| updated_at | DATETIME | DEFAULT CURRENT_TIMESTAMP ON UPDATE | 最近上报（在线判定依据） |
| source | VARCHAR(20) | DEFAULT 'client' | client=客户端识别 / manual=后台手工标记 |
| visibility | ENUM('public','members_only','private') | DEFAULT 'public' | 可见性 |
| created_at | DATETIME | DEFAULT CURRENT_TIMESTAMP | 创建时间 |

索引：`uk_user`、`idx_game_key`、`idx_updated`、`idx_visibility`

> 与 `group_roster.is_online`（VRChat 在线）两套并存互不覆盖（契约 §2.2 备注）。

### 3.3 `jtt_bind_codes` — 绑定码表（方向④）

| 字段 | 类型 | 约束 | 说明 |
|---|---|---|---|
| id | INT | PRIMARY KEY AUTO_INCREMENT | 主键 |
| code_hash | VARCHAR(64) | NOT NULL UNIQUE | 绑定码 SHA-256 哈希（原始码仅生成时返回一次，库中不存明文） |
| user_id | INT | NOT NULL | 目标站内用户（users.id，注册后绑定到 jtt_accounts.user_id） |
| display_name | VARCHAR(100) | NULL | 注册时快照的显示名 |
| role | VARCHAR(20) | DEFAULT 'member' | 注册后境途侧角色 |
| expires_at | DATETIME | NOT NULL | 过期时间（默认 7 天） |
| used_at | DATETIME | NULL | 使用时间（NULL=未使用） |
| used_by | VARCHAR(64) | NULL | 使用方账号 ID（`jt_` 前缀） |
| created_by | INT | NOT NULL | 生成人（users.id，即 super_admin） |
| created_at | DATETIME | DEFAULT CURRENT_TIMESTAMP | 创建时间 |

索引：`uk_code_hash`、`idx_user`、`idx_expires`、`idx_used`

## 4. 错误码（utils.js 追加 11 个）

| code | HTTP | 场景 |
|---|---|---|
| `JTT_SIGNATURE_INVALID` | 401 | 验签失败 / 缺少签名头 |
| `JTT_TIMESTAMP_STALE` | 401 | 时间戳超窗 |
| `JTT_ACCOUNT_REVOKED` | 401/409 | 文件已撤销 |
| `JTT_ACCOUNT_EXPIRED` | 401/409 | 文件已过期 |
| `JTT_ACCOUNT_EXISTS` | 409 | 用户已有有效文件，需先撤销或 force |
| `JTT_ACCOUNT_NOT_FOUND` | 404/401 | 记录不存在 |
| `JTT_GAME_INVALID` | 400 | 游戏 key 非法 |
| `DEEPLINK_TYPE_INVALID` | 400 | 深链类型不在白名单 |
| `JTT_BIND_CODE_INVALID` | 400 | 绑定码不存在 / 格式非法 |
| `JTT_BIND_CODE_USED` | 409 | 绑定码已被使用（一次性） |
| `JTT_BIND_CODE_EXPIRED` | 409 | 绑定码已过期 |

（其余 `USER_NOT_FOUND`、`USER_UNAVAILABLE`、`FORBIDDEN`、`RATE_LIMITED` 沿用现有错误码。）

## 5. CSRF 豁免与限流

- `server/middleware/csrf.js` 豁免路径追加（相对 `/api` 书写）：
  - `/jtt/accounts/verify`、`/jtt/accounts/register`、`/jtt/states` —— 签名端点不依赖 Cookie 会话，CSRF 安全由 ED25519 签名保证（契约 §6.2）。
- 管理端点 `/jtt/bind-codes`、`/jtt/accounts/issue` 等**不在**豁免列表：走 Session + CSRF 双重校验（契约 §6.2）。
- 全局 DDoS 限流（600 次/分/IP）对 `/api/jtt/*` 同样生效。
- 状态上报另有内存级限流：≤1 次/15s/accountId（`stateReportCache`，超限 429 `RATE_LIMITED`）。

## 7. 后期实施计划（按契约 §8 实现顺序）

1. **打通签发链路（§3）**：`accounts/issue` → `accounts/export/:id` 串通，先在后台完成"签发 → 下载 .jttaccount"闭环；列表/详情/撤销同步补齐。
2. **签名认证落库（§4）**：实现 `jttAuth` 的查库验签（按 accountId 加载 `jtt_accounts`、校验 revoked/expires_at）、nonce 防重放、RAW_BODY 捕获；随后 `states` 三端点落库。
3. **方向④ 注册与绑定码（§3.7/§3.8）**：实现 `bind-codes`（生成/哈希落库/7 天过期）与 `accounts/register`（绑定码校验 → TOFU 验签 → 幂等落库 → 标记已用），打通"客户端超管创建账号文件 → 绑定码注册联动"闭环。
4. **深链生成（§5）**：`deeplink/generate` 构造 `jt1://` 链接 + 票据表；Web 前端 `/launch` 落地页（纯静态）。
5. **前端页面**：后台签发管理页、绑定码管理页、成员/频道视图"正在玩 XX"与"一起玩"入口。
6. **客户端对接**：`@jingtup/core` **超管创建账号文件**（ED25519 密钥对 + 口令加密 + 绑定码注册；创建权限仅限客户端超管，普通用户不可自助创建）、状态上报定时器、`jt1://` 协议注册、**用户数据导出备份（`jingtup/backup@1`，口令加密 AES-256-GCM）**。
7. **回归与加固**：`route_guard` 启动自检、限流与豁免验证、`node --check` 全量通过。

## 8. 待确认事项（契约 §7，联调前需决策）

1. **密钥对生成方**：推荐客户端生成 ED25519 密钥对、仅将公钥交给 Web 签发（Web 永不接触私钥）；备选 Web 代生成（需加密存储私钥，安全性降级）。决定后 §3.1 的 `encryptedSecret` 字段按需保留/删除。
2. **防重放**：`jtt_deeplink_tickets` 表与 `jtt_nonce` 表是否落地，或先用内存缓存（重启失效，可接受）。
3. **状态 TTL**："15 分钟离线"阈值是否可配置（建议 `system_config` 加键 `jtt_state_ttl_minutes`）。
4. **角色映射**：web `admin` 是否映射为境途 `admin`（可签发子账号文件），还是统一只给 `member`。
5. **账号文件格式互通**：契约 `jttAccountFile` 字段须与 `@jingtup/core` 的 `AccountFile` 定义逐字段对齐后再定稿。
6. **注册开放度**：绑定码是否可直接"创建站内用户"，还是仅允许绑定既有 users 记录（当前骨架取后者：`user_id` 必填）。
7. **纯离线账号并存**：未联动的本地账号（纯离线可用）与已联动账号如何共存、显示区分、是否可后续补注册。
8. **备份文件格式**：客户端数据导出备份 `jingtup/backup@1`（口令加密 AES-256-GCM，含账号文件/自定义游戏库/配置/吊销清单）字段定义是否纳入本期联调验收。

```bash
# 5) 管理端生成绑定码（无 CSRF）→ 403 CSRF 拦截
curl -X POST http://localhost:3456/api/jtt/bind-codes -H "Content-Type: application/json" -d '{"userId":1}'
```
