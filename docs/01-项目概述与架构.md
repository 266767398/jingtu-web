# 境途同游 Web 项目：概述与架构

> 审计基线：2026-09-02 当前工作树（包括未提交文件）。本文只描述能够从 `public/`、`server/` 及其直接启动/部署脚本验证的现状。

## 一、项目定位与已接入能力

境途同游是面向 VRChat 社群的单体 Web 应用。浏览器端由原生 HTML、CSS 和 JavaScript 构成，Node.js/Express 同时提供静态文件、HTTP API 与 WebSocket 服务，业务数据和 Session 默认存放在 MySQL（可通过 `JINGTU_DB_ENGINE=sqlite` 切换为 Node 内置 `node:sqlite` 的嵌入式 SQLite 模式，见 §2.1 与 `docs/27`）。

当前主页面已接入：

- 本地密码、VRChat 登录与 2FA、首次初始化、密码重置；
- 首页统计、成员、VRChat 群组、公告、活动、生日、相册、收藏、动态；
- 私信、群聊、在线状态及位置共享；
- 通知、个人资料、权限组及管理功能；
- 活动报名、活动签到和活动组队；
- 好友（申请/响应/拉黑/互关/共同好友）、关注与粉丝、统一收藏馆（收藏夹与收藏项、评分、失效检测）；
- 直播列表/播放、观看人数、点赞和评论。直播源由服务端记录并交给 HTML `<video>` 播放，浏览器端没有 WebRTC 推流实现，评论使用 HTTP 轮询而非 WebSocket。

需区分“存在代码”和“主站已接入”：

- `public/js/checkin.js`、`achievements.js` 及对应 CSS 存在，后端也挂载了每日签到和成就 API，现由 `loader.js` 按 Tab 懒加载（均列入 `ROUTE_MODULES`，访问“我” Tab 时加载），不再由 `index.html` 逐行声明；
- `public/js/friends.js`、`follows.js`、`collections.js` 由 `loader.js` 在对应 Tab 首次渲染时懒加载；
- `public/js/admin-db.js` 仍未由主页面加载；
- 收藏（favorites 旧收藏夹）和直播已由导航、页面脚本及 API 接入；
- 积分、商城、装扮、排行榜和小游戏等不能从当前 `public/`、`server/` 证明为已实现功能。

## 二、实际技术栈

### 2.1 服务端

`server/package.json` 的包版本为 `1.3.0`，主要依赖版本范围如下：

| 分类 | 实现 |
|---|---|
| 运行时与框架 | Node.js、Express `^4.22.2` |
| 数据库 | 默认 MySQL；`mysql2/promise`（mysql2 `^3.22.4`）连接池。可选 SQLite 模式：设 `JINGTU_DB_ENGINE=sqlite` 后 `server/db.js` 就地 patch `mysql2/promise` 的 `createConnection/createPool`，改用 Node 内置 `node:sqlite`（`DatabaseSync`）作为嵌入式存储，库文件默认 `server/data/jingtu.sqlite`（`JINGTU_SQLITE_PATH` 可覆盖） |
| Session | `express-session ^1.19.0` + `express-mysql-session ^3.0.3` |
| 密码与校验 | `bcryptjs ^3.0.3`、`express-validator ^7.3.2` |
| 上传与媒体 | Multer `^1.4.5-lts.1`、Sharp `^0.35.3`、FFmpeg installer |
| 实时通信 | `ws ^8.21.0` |
| HTTP | Axios、CORS、compression、express-rate-limit |
| 调度与通知 | node-schedule、cron、Nodemailer |
| 可选缓存 | redis `^6.1.0`，并有本地缓存服务 |
| API 文档 | swagger-jsdoc、swagger-ui-express（位于 `devDependencies`） |
| 测试配置 | Jest、Supertest、jest-junit |

数据库代码明确考虑 MySQL 5.7，仓库内 Windows 启动脚本也指向 MySQL 5.7.26，因此不能把 MySQL 8.0+ 写成硬性要求。MySQL 为默认行为；SQLite 模式（`JINGTU_DB_ENGINE=sqlite`）在 `db.js` 内提供完整 SQL 重写层（DDL/ALTER/SHOW/information_schema/时间函数/UPSERT 等 MySQL 方言均转换到 SQLite 语法），不依赖外部 MySQL，具体规则与验证见 `docs/27`。

Swagger UI 和 JSON 分别挂载到 `/api-docs`、`/api-docs.json`。`server.js` 仅在非 `production` 环境加载 Swagger（lazy require + try/catch），相关包位于 `devDependencies`；生产可用 `npm ci --omit=dev` 而不缺依赖。

### 2.2 浏览器端

- 无 React/Vue、打包器或前端模块系统，静态资源由 `index.html` 直接加载；
- 页面切换由 `switchTab()` 控制 `tab-*` 元素显隐，不是 History/hash URL 路由；
- API 使用原生 Fetch/XHR、Cookie Session 和自定义 CSRF 请求头；
- 实时客户端使用原生 WebSocket，另使用 Notification、Geolocation、Web Audio 等浏览器 API；
- 自定义 i18n 支持中文、英文、日文、法文、德文、俄文；
- 主样式由 `style.css` 导入八个拆分样式文件，并额外加载 `ui-enhance.css`、`favorites.css`；
- 地图脚本会从 CDN 动态加载 Leaflet 1.9.4，并使用 OpenStreetMap 等外部瓦片服务；活动二维码也会调用第三方图片服务。因此主页面虽未静态引用前端框架，部分功能仍依赖外部库和网络服务。

### 2.3 当前未进入启动链路的组件

- Redis 客户端和缓存封装存在，但 `server.js` 未调用 `initCache()`；Session 使用 MySQL，不使用 Redis；
- 邮件模块存在，但启动时只被加载，未调用 `initMailer()`；
- `tasks.js` 也只被加载，未调用 `startTasks()`；
- 实际启动的是 `schedule.js` 中的八项任务：缓存预热、回收站清理、活动归档、邀请过期、Token 提醒、活动提醒、VRChat 成员状态刷新、在线成员缓存刷新。

## 四、启动与请求架构

### 4.1 启动方式

仓库根目录没有 `package.json`。npm 命令须在 `server/` 执行：

```text
cd server
npm install
npm start
```

`npm start` 等价于 `node server.js`。服务：

1. 从项目根目录 `.env` 读取配置；
2. 创建 Express 应用和纯 HTTP Server；
3. 注册中间件、静态目录、HTTP 路由、Swagger 和 `/ws`；
4. 异步执行 `db_init.js`；成功后启动 `schedule.js`，初始化失败只记录警告，HTTP 服务仍会监听；`JINGTU_DB_ENGINE=sqlite` 时 `db_init.js` 直接对 `server/data/jingtu.sqlite` 建表（无需外部 MySQL）；
5. 默认监听 `0.0.0.0:3456`；
6. 在 SIGTERM、SIGINT、SIGHUP 时关闭 HTTP、WebSocket、数据库和调度任务。

当前进程没有 HTTPS Server、证书加载或 HTTP 到 HTTPS 的重定向。生产环境仅设置 HSTS 响应头；TLS 需要由外部反向代理终结。

### 4.2 静态映射

| URL | 实际目录 |
|---|---|
| `/uploads` | 根目录 `uploads/` |
| `/assets` | 优先匹配根目录 `assets/`；未命中时继续由 `public/` 静态映射处理 |
| `/backups` | 根目录 `backups/` |
| `/` | 根目录 `public/`，`maxAge: 0` 且关闭 ETag |

根目录 `assets/` 包含群组图片，`public/assets/` 包含 PWA 图标；由于 Express 静态中间件会在文件未命中时继续向后匹配，这两类资源都可使用 `/assets/...` URL。

### 4.3 中间件顺序

实际主链路为：

```text
CORS
→ compression
→ CSP/安全响应头
→ /api DDoS 限流
→ 可疑请求检测
→ 指标与 API 版本中间件
→ 请求体大小检查
→ JSON 解析（20 MB）
→ WAF（注册于 JSON 解析之后，可扫描已解析的 JSON 请求体）
→ UTF-8 响应包装
→ 静态文件（/uploads 例外：挂载于 Session 之后并先鉴权）
→ Session
→ 已登录用户存在/封禁校验
→ 登录/上传/管理/搜索细分限流
→ CSRF
→ 业务路由
→ 全局错误处理
```

CSRF 对 GET、HEAD、OPTIONS 以外的方法生效，但登录、初始化、密码重置、setup 和 migration 等明确路径豁免。Token 绑定 Session ID、有效期一小时且可重复使用。

### 4.4 Session、角色与限流

- Session 默认写入 MySQL `sessions` 表，七天过期；MySQL Store 模块加载失败才回退进程内 MemoryStore（SQLite 模式下 Store 连不上 MySQL，同样回退 MemoryStore，登录态不跨进程持久化）；
- Cookie 为 `httpOnly`、`sameSite=lax`、滚动续期；`secure` 为 `'auto'`——经 HTTPS（`req.secure`，依赖 `trust proxy` 解析 `X-Forwarded-Proto`）时自动加 `Secure`，纯 HTTP 则不加；
- 未配置 `SESSION_SECRET` 时会生成仅当前进程有效的临时密钥；
- 应用角色为 `super_admin`、`admin`、`member`；待审核和封禁是用户状态，不是第四个角色；
- 密码使用 bcrypt 成本因子 12；
- 限流值：`/api` 每 IP 每分钟 600 次；登录 15 分钟 5 次；上传每分钟 10 次；管理接口每分钟 30 次；搜索 30 秒 20 次。

## 六、实时通信

### 6.1 站内 WebSocket

- 与 HTTP 共用 Server，固定路径 `/ws`；
- 浏览器登录成功后连接当前源的 `ws://.../ws` 或 `wss://.../ws`；
- 服务端验证 Origin、签名的 `connect.sid`，并从 Session Store 读取含 `userId` 的会话；
- 支持在线用户、通知、私信、群聊、正在输入、位置更新/停止等消息；
- 服务端每 30 秒发送 JSON `ping` 并以收到 `pong` 更新时间，空闲 10 分钟强制离线；当前客户端也主动发送 `ping`，但没有处理服务端 `ping`，双方心跳消息并不对称，连接可能在约 10 分钟后被判定超时；
- 客户端断线最多重试 10 次并使用指数退避；
- HTTP 与 WebSocket 都有消息持久化路径；在线文本私信和群聊优先通过 WebSocket 发送并由服务端写入数据库。

### 6.2 VRChat 实时链路

`server.js` 还创建 `vrc_pipeline.js`：系统 VRChat Cookie 可用时连接 VRChat Pipeline，并把 VRChat 通知、好友事件及群组统计广播给站内客户端。这与站内 `/ws` 服务是两条不同链路。

直播评论不走上述 WebSocket，当前前端每 5 秒轮询 HTTP API。

## 七、PWA 与部署现状

### 7.1 PWA

- `index.html` 引用了 `manifest.json`，Manifest 声明 `standalone`、作用域 `/` 和四个图标；
- `sw.js` 存在，对带 `?v=` 版本号的 JS/CSS 采用 cache-first（版本号变即资源变、命中即返回、二次访问零网络），对同源非 `/api/` 其余请求采用网络优先、缓存兜底；HTTP 局域网访问由服务端 `Cache-Control: immutable` 兜底；
- `index.html` 现已在 `window load` 后调用 `navigator.serviceWorker.register('/sw.js')`，**Service Worker 已注册启用**（HTTPS 或 localhost 生效；非安全上下文静默忽略）；
- 预缓存仅包含 `/`、主 CSS、Manifest 和四个图片资源，不含主 JavaScript、语言包及全部样式；

因此当前可确认“Manifest + 已注册 Service Worker + 版本化资源 cache-first”，但不能宣称完整离线（主 JS/语言包未进预缓存）或已通过可安装性审核。

### 7.2 部署

- 仓库可确认的生产入口是 Node HTTP/WS 服务，反向代理和 TLS 需外部配置（应用不内置 HTTPS Server，由 Nginx / 宝塔终结）；
- `install.sh` 已改为可用的部署脚本：检测/安装 Node 20、安装依赖、生成 `.env`（密钥自动随机）、可选建库、执行 `db_init.js`、生成 PM2 `ecosystem.config.js` 并启动、生成 Nginx 反代模板；详见 `DEPLOY.md`；
- `start-services.ps1/.bat` 是 Windows 本机控制面板（见 `面板建议.md`），不再写死 phpStudy 路径；
- 仓库现已提供 Docker 部署：`Dockerfile`、`docker-compose.yml`（app + MySQL）、`docker-entrypoint.sh`、`.dockerignore`、`docker.env.example`；以及 `ecosystem.config.js`（PM2）、`deploy/nginx/jingtu.conf`（Nginx/宝塔反代模板）；
- `nginx.htaccess` 的内容是 Apache `.htaccess` 指令，不是可直接使用的 Nginx 配置；请以 `deploy/nginx/jingtu.conf` 为准。

据此仓库已具备 Docker、Nginx（反代模板）、PM2 与宝塔一键部署能力；systemd unit 仍未提供（可用 PM2 `startup` 替代开机自启）。
