## 2. 认证与权限

- bcrypt cost 12；密码强度 ≥8 位 + 大小写 + 数字（前后端口径存在差异，以实际校验为准）。
- 角色阈值：member(2) / admin(3) / super_admin(4)；`requireAdminCompat` = admin 及以上。
- VRChat 凭据：QQ 用 AES-256-CBC、VRChat Cookie 用 AES-256-GCM（`ENCRYPT_KEY` 64hex）。

## 3. 安全中间件

| 防线 | 实现 |
|---|---|
| 限流 | 5 类分层（全局 600/分、登录 5/15 分、上传 10/分、管理 30/分、搜索 20/30 秒），HybridStore |
| WAF | 注册于 `express.json()` 后，扫描 URL/query/已解析 JSON body（值+键+URL 解码复扫） |
| CSRF | Token 绑定 SessionID，Map+Redis 双写，TTL 1h，15 分钟清理，超 1 万条淘汰一半 |
| 安全头 | nosniff / X-Frame-Options DENY / Referrer-Policy / CSP（script/style 仍 unsafe-inline）/ 生产 HSTS |
| 上传 | 全路由扩展名+魔数双闸 + `secureUpload` 白名单 + 分档大小限制 |
| 静态 | `/uploads` 登录或 `?share=<code>` 令牌；`/backups` 仅管理员 API |
| 在线更新 | 仅超管 + CSRF + execFile 数组直传 + `GIT_TERMINAL_PROMPT=0` |

## 4. 已知边界（非缺陷，设计如此）

- 单进程单实例（CSRF/限流计数/WS 在线映射/VRC 状态在内存）——**禁止 cluster/多副本**。
- 直播为元数据模式，无推流/转码/HLS 后端。
- 邮件/每日汇总依赖 `SMTP_*` 配置，未配置时静默跳过。
- CSP 内联脚本依然存在（index/migration 页内联），未达严格 CSP。
